Wan2.1 长序列并行适配方案Adapting Wan2.1 for Long-Sequence Parallelism

这是我给 Wan2.1 14B 图生视频模型做长序列并行适配的一份方案记录,代码在昇腾生态贡献仓 msit / eco-contrib,入口脚本是 scripts/train_i2v_full_14B_sp2_8p.sh。要解决的问题很具体:同一个模型,不开序列并行要 两机 32 卡,开了之后 单机 8 卡 就能训。

这篇按开发顺序写:先讲清楚序列并行要解决什么、为什么选 DeepSpeed-Ulysses,再落到三个改动点的具体代码,然后算清通信量、把梯度对齐这件事讲透,最后是四处容易踩坑的工程细节和一份验证清单。想直接看能跑的代码,可以跳到第八节。This is my write-up of adapting Wan2.1's 14B image-to-video model for long-sequence parallelism. The code lives in Ascend's msit / eco-contrib repository, with scripts/train_i2v_full_14B_sp2_8p.sh as the entry point. The problem is concrete: the same model needs 32 cards across two nodes without sequence parallelism and trains on 8 cards in one node with it.

The note follows the order the work happened in: what sequence parallelism is for and why DeepSpeed-Ulysses is the right fit here, then the three places the code actually changes, then the communication ledger and how to get gradients right, and finally four engineering details that are easy to get wrong plus a verification checklist. If you just want working code, skip to section 8.

一、方案选型:为什么是 Ulysses1 · Choosing a scheme: why Ulysses

序列并行(SP,也叫上下文并行 CP)要解决的是一件别的并行方式解决不了的事:单个样本的激活放不下。张量并行切权重矩阵,流水并行切层,数据并行切 batch —— 当 batch 已经是 1、一个样本的激活仍然爆显存时,能切的就只剩序列这一个维度了。Sequence parallelism (SP, also called context parallelism) exists for a situation the other forms cannot address: a single sample's activations do not fit. Tensor parallelism shards weight matrices, pipeline parallelism shards layers, data parallelism shards the batch — when the batch is already 1 and one sample's activations still overflow memory, the sequence is the only dimension left to cut.

而切序列的难点自始至终只有一个:注意力需要看到全部 token。主流的三条路,区别就在于用什么办法绕开它:And sharding the sequence has exactly one difficulty: attention needs to see every token. The three mainstream schemes differ only in how they get around it:

这个模型选 Ulysses,理由有三条。第一,注意力实现一行都不用改 —— 转置之后每卡手里是完整序列,注意力退化成一次普通 SDPA;Ring Attention 则要重写在线 softmax,在 NPU 上还得重新对齐算子,工作量完全不是一个量级。第二,通信量随 SP 度递减:all-to-all 每卡收发本地分片的 (sp−1)/sp,而本地分片本身又是全量的 1/sp,两者相乘之后总量随 SP 增大而下降;Megatron-SP 的 all-gather 是全量的,不随 SP 降。第三,head 数够用:这个模型 40 个 head,SP=2 只用掉 2,离上限还很远。Three reasons Ulysses fits this model. First, the attention implementation needs no changes at all — after the transpose each card holds a complete sequence, so attention degenerates into an ordinary SDPA. Ring Attention would mean rewriting the online softmax and re-tuning kernels on NPU, an entirely different order of effort. Second, communication falls as the SP degree rises: an all-to-all moves (sp−1)/sp of the local shard, and the local shard is itself 1/sp of the whole, so the product shrinks with SP. Megatron-SP's all-gather moves the full tensor regardless. Third, there are enough heads: this model has 40, and SP=2 spends only 2 of them — far from the ceiling.

选型时最该先问的一个问题:SP 组会不会跨节点? all-to-all 是全连接通信、每层要做 8 次、而且完全挡在计算路径上。这类通信必须待在节点内的高带宽域里 —— 一旦 SP 组跨机走 IB,性能会直接塌方。单机 8 卡、SP=2 意味着一个 SP 组只占 2 张卡,天然在机内,这是这套方案成立的隐含前提。几种并行方式的通信量与重叠性对比,可以看通信量账本和序列并行与通信两篇。The first question to ask when choosing: will an SP group ever straddle nodes? An all-to-all is fully connected, runs 8 times per layer, and sits squarely on the critical path. That class of communication has to stay inside the node's high-bandwidth domain — the moment an SP group spans machines over IB, throughput collapses. Eight cards in one node at SP=2 puts two cards in each group, comfortably intra-node, and that is the unstated premise the whole scheme rests on. For how the parallel strategies compare on volume and overlappability, see the communication ledger and sequence parallelism and communication.

落到代码上,只有三个改动点In code, it comes down to three touch points

序列并行听起来要动整个模型,实际落到代码里只有三处。把这三处认出来,剩下的都是细节:Sequence parallelism sounds like it touches the whole model; in the code it is three places. Recognise those three and the rest is detail:

为什么必须动注意力?因为切完序列之后,除注意力以外的所有算子都不受影响。LayerNorm、FFN、残差都是沿 hidden 维逐 token 独立计算的,每张卡拿着自己那半段序列照算就行。只有注意力需要「看到全部 token」—— 这是序列并行唯一真正的难点,也是 Ulysses 要解决的。Why must attention change? Because once the sequence is sharded, every operator except attention is unaffected. LayerNorm, FFN and the residual all work token-by-token along the hidden dimension, so each card computes on its own half of the sequence. Only attention needs to see all tokens — that is the single real difficulty in sequence parallelism, and what Ulysses exists to solve.

二、形状账:32,760 是怎么来的2 · Shapes: where 32,760 comes from

代码注释里到处是 [1, 32760, 5120]。这个数不是随手写的,它决定了后面所有通信量:The code comments are full of [1, 32760, 5120]. That number is not arbitrary — it sets every communication volume below:

81 帧 → VAE 时间轴 4× 下采样 → 21 个 latent 帧
480×832 → VAE 空间 8× → 60×104 → patch (1,2,2) → 30×52
21 × 30 × 52 = 32,760 token  ·  dim 5120 · 40 heads · head_dim 128 · 40 层81 frames → VAE 4× temporal downsample → 21 latent frames
480×832 → VAE 8× spatial → 60×104 → patch (1,2,2) → 30×52
21 × 30 × 52 = 32,760 tokens  ·  dim 5120 · 40 heads · head_dim 128 · 40 layers

于是有一个贯穿全文的锚:一份完整的激活张量 = 32,760 × 5,120 × 2 B = 320 MiB。DiT 有 40 层,开了梯度重计算也要在每层边界存一份,单卡就是 12.5 GiB。SP=2 把它砍到 6.25 GiB —— 这是序列并行省显存的主体部分。That gives one anchor for the whole note: one full activation tensor = 32,760 × 5,120 × 2 B = 320 MiB. With 40 DiT layers, even under gradient checkpointing one copy is kept at each layer boundary, so 12.5 GiB per card. SP=2 halves that to 6.25 GiB — the bulk of what sequence parallelism saves.

为什么不能靠加卡解决? 加 DP 卡摊薄的是 batch,不是序列。这里 batch_size=1 已经到底了,单个样本的激活就是 12.5 GiB,再加多少张卡它都不变。要让单卡激活下降,只能切序列 —— 这是 SP 存在的全部理由。Why not just add cards? Adding DP ranks thins out the batch, not the sequence. Here batch_size=1 is already the floor, and one sample's activations are 12.5 GiB no matter how many cards you add. The only way to shrink per-card activations is to shard the sequence — which is the entire reason SP exists.

三、切分与恢复:一对自定义 autograd3 · Split and gather: a pair of custom autograd functions

主干 forward 里就两行,但它们是一对互逆的 autograd.Function,前向做通信、反向做反向通信:Two lines in the backbone forward, but they are a mutually inverse pair of autograd.Functions: communication forward, the mirror image backward:

x, (f, h, w) = self.patchify(x)      # [1, 32760, 5120]

    x = checkpoint(block, x, context, t_mod, freqs, use_reentrant=True)

    x = recover_parallel_data_for_sp(x, dim=1, sp_size=sp_size)

这里有两个细节必须做对。第一,freqs 要跟着 x 一起切,而且要用同一个函数、同一个 rank 顺序 —— RoPE 是位置相关的,每张卡必须拿到自己那段 token 对应的频率,漏切或者错序,位置编码就整体错位了。第二,RoPE 必须在 all-to-all 之前施加,也就是趁着还是「按序列切」的布局:此时每张卡清楚自己持有哪些绝对位置,一旦转成「按 head 切」,这个信息就没了。Two details have to be right here. First, freqs must be sharded together with x, through the same function and the same rank ordering — RoPE is positional, so each card needs the frequencies for its own token range; forget to shard it, or shard it in a different order, and the positional encoding is uniformly misaligned. Second, RoPE must be applied before the all-to-all, while the layout is still sequence-sharded: at that moment each card knows which absolute positions it holds, and once the layout flips to head-sharded that information is gone.

四、Ulysses:靠两次转置把注意力变回本地计算4 · Ulysses: two transposes turn attention back into a local computation

Ulysses 的想法很干脆:注意力需要完整序列,那就在算注意力的那一刻把布局换过来。平时每卡持有「一段序列 × 全部 head」,进注意力前用一次 all-to-all 转成「完整序列 × 一部分 head」,算完再转回去。转置之后每张卡手里是完整序列,注意力就退化成一次普通的本地 SDPA,一行都不用改。Ulysses' idea is blunt: attention needs the full sequence, so change the layout at the moment attention runs. Normally each card holds "a slice of the sequence × all heads"; one all-to-all before attention flips it to "the full sequence × a subset of heads", and another flips it back afterwards. After the transpose each card holds a complete sequence, so attention degenerates into an ordinary local SDPA — not a line of it needs changing.

代码里这件事是交给 DeepSpeed 现成的封装做的,自己只提供一个「本地注意力」函数:In the code this is delegated to DeepSpeed's existing wrapper, with only a "local attention" function supplied: 

def flash_attention_sequence_parallelism(
        q, k, v, compatibility_mode=False):
    # 转置之后每卡都持有完整序列,这里就是一次普通 SDPA
    return F.scaled_dot_product_attention(q, k, v)

self.dist_attn = DistributedAttention(
    local_attention=flash_attention_sequence_parallelism,
    sequence_process_group=get_sequence_parallel_group(),
    scatter_idx=1,   # 沿 num_heads 维散开

scatter_idx=1 / gather_idx=2 对应张量布局 [b, n, s, d]:把 head 维散出去、把 seq 维收回来。DistributedAttention 内部对 q、k、v 各做一次 all-to-all,算完再对输出做一次 —— 每次注意力 4 次 all-to-all。自注意力和交叉注意力各一份,所以每层 8 次。scatter_idx=1 / gather_idx=2 refers to the layout [b, n, s, d]: scatter the head dimension, gather the sequence dimension. DistributedAttention runs one all-to-all each for q, k and v, plus one on the output — 4 all-to-alls per attention. Self-attention and cross-attention each get a set, so 8 per layer.

五、通信量账本:每层 8 次 all-to-all 花在哪5 · The communication ledger: where the 8 all-to-alls per layer go

接上通信,第一件事就是把账算清楚 —— 不然优化只能靠猜。一次 all-to-all 每张卡收发本地张量的 (sp−1)/sp,把上面的 320 MiB 锚代进去,一层的账就完整了:Once communication is in the picture, the first job is to price it — otherwise optimisation is guesswork. One all-to-all moves (sp−1)/sp of the local tensor per card; substituting the 320 MiB anchor from above closes the books on a layer:

这张账单里藏着一个能省下三分之一通信的机会,值得单独讲:交叉注意力其实一个字节都不用传。Buried in that bill is an opportunity to cut a third of the traffic, and it deserves its own explanation: cross-attention need not move a single byte.

Ulysses 之所以要 all-to-all,是因为 k / v 被切开了,每张卡看不到完整序列。但交叉注意力的情况不一样:它的 q 来自被切开的视频 latent,k / v 却来自文本上下文 —— 而文本上下文在每张卡上都是完整的一份 512 token,从头到尾没被切过。前提不成立,手段自然就不必要:每张卡拿自己那段 q 和完整的 k / v 直接做本地注意力,结果就是正确的。Ulysses needs the all-to-all because k and v are sharded and no card sees the whole sequence. Cross-attention is different: its q comes from the sharded video latents, but k and v come from the text context — and the text context is a complete 512-token copy on every card, never sharded at any point. The premise does not hold, so the machinery is not needed: each card can attend its own q slice against the full k/v locally and get the right answer.

如果图省事,把 q / k / v 一股脑交给 DistributedAttention,k / v 也会跟着走一遍 all-to-all,512 长度的上下文被沿 seq 维拼接成 512×sp,同一份文本复制了 sp 遍。值得注意的是这不会算错:softmax 对重复的 key 会把权重均分,加权和与不复制时逐位相等 —— 我拿一组随机数对拍过,差值是 0。正因为不报错也不失真,这类开销特别容易一直留在代码里,只能靠算账发现。Take the shortcut of handing q, k and v all to DistributedAttention and k/v go through the all-to-all as well: the 512-token context gets concatenated along seq into 512×sp, the same text duplicated sp times. Worth noting that this does not compute a wrong answer: softmax spreads the weight evenly over duplicated keys, and the weighted sum is bit-identical to the undulplicated case — I checked it against random values and the difference was exactly 0. Precisely because nothing errors and nothing drifts, overheads of this shape tend to survive in a codebase indefinitely; only the ledger finds them.

同一个文件里就有可以照搬的写法。 I2V 分支处理图像条件 k_img / v_img 时,用的就是不带任何通信的本地 flash_attention,吃的正是切开后的 q。文本这一路按同样的形状写即可,具体代码在第八节第 2 步。判断标准可以记成一句话:一个张量有没有被切过,决定了它要不要进 all-to-all。A pattern to copy sits in the same file. In the I2V branch, the image-condition path k_img / v_img already uses a plain local flash_attention with no communication, fed by exactly the sharded q. The text path takes the same shape — the code is in step 2 of section 8. The rule of thumb is one sentence: whether a tensor was ever sharded decides whether it belongs in the all-to-all.

六、梯度怎么对齐:grad_scale 该放在哪6 · Aligning gradients: where grad_scale belongs

这是整套适配里最微妙、也最容易被跳过的一步。开了 SP 之后,一个 SP 组里的 2 张卡跑的是同一个样本的不同片段,它们算出的参数梯度是同一个样本梯度的两个部分,应该相加。但外层的数据并行不知道这件事 —— DeepSpeed 看到的是 8 张卡,它把 8 份梯度取平均。而这 8 张卡实际只对应 4 个独立样本,于是每个样本的梯度被多除了一次 sp,整体小了 2 倍。This is the subtlest step in the whole adaptation, and the easiest to skip. With SP on, the two cards in a group process different slices of the same sample, so the parameter gradients they produce are two parts of one sample's gradient and should be summed. The outer data-parallel layer knows nothing about this — DeepSpeed sees 8 cards and averages 8 gradients. Those 8 cards represent only 4 distinct samples, so each sample's gradient is divided by sp one extra time and comes out 2× too small.

补偿的位置有得选,最顺手的一处是那两个 autograd 边界:恢复那一侧反向时 mul_(sp),切分那一侧反向时 div_(sp)。写起来很自然,但落地前要先看清一件事 —— 这两个缩放的作用范围并不重合:There is a choice of where to compensate, and the handiest spot is the two autograd boundaries: mul_(sp) on the gather side's backward, div_(sp) on the split side's. It reads naturally, but before committing to it there is one thing to check — the two scalings do not cover the same ground:

loss → head → recover(×sp) → 40 个 DiT block → prepare(÷sp) → patchify
 
SP 区内部(40 个 block 的权重): ×sp
SP 区外部(head、patch_embedding): ×sp 再 ÷sp = ×1loss → head → recover(×sp) → 40 DiT blocks → prepare(÷sp) → patchify
 
Inside the SP region (the 40 blocks' weights): ×sp
Outside it (head, patch_embedding): ×sp then ÷sp = ×1

一乘一除只覆盖夹在中间的那一段。结果是 DiT 主干拿到了补偿,而夹在 SP 区外面的输入投影和输出头没有,两者之间差了 sp 倍的有效学习率,SP=2 就是 2 倍。这不会让训练崩掉 —— 参数量上主干占绝对多数,patch_embedding 和 head 也照样在学 —— 但它是一个隐式的、随 SP 度漂移的超参:换个 SP 度,这两部分的相对学习率就跟着变,做消融或者复现实验时极难定位。One multiply and one divide only cover what lies between them. The result is that the DiT backbone gets compensated while the input projection and output head, which sit outside the SP region, do not, leaving an effective learning-rate gap of sp between them — a factor of 2 at SP=2. It will not blow training up: the backbone dominates the parameter count, and patch_embedding and head still learn. But it is an implicit hyperparameter that drifts with the SP degree — change SP and the relative learning rate of those two parts changes with it, which is brutal to locate during an ablation or a reproduction.

所以这一步的结论是选位置,而不是选倍数:缩放要放在能覆盖全部参数的地方。把两侧的 grad_scale 都关掉,让切分与恢复退回成纯粹的数据搬运,然后在 loss 上乘一次 sp —— 主干和 head 就拿到同一个尺度,SP 度对学习率也就中性了。代码在第八节第 3 步。So the decision here is about placement, not about the factor: put the scaling somewhere that covers every parameter. Turn off grad_scale on both sides so that split and gather go back to being pure data movement, then multiply the loss by sp once — backbone and head then share one scale, and the SP degree becomes neutral with respect to learning rate. The code is in step 3 of section 8.

七、四处最容易踩的工程细节7 · Four engineering details that bite

前面几节讲的是「怎么算对」,这一节讲的是「怎么跑起来不出事」。下面四条是这类适配里翻车率最高的地方,每一条我都写了最小复现脚本验过。前两条关系到正确性,后两条关系到可维护性 —— 共同点是都不会在单机 8 卡的冒烟测试里暴露。The previous sections were about computing the right thing; this one is about not getting burned in production. These four are where adaptations like this most often go wrong, and I wrote a minimal reproduction for each. The first two affect correctness and the last two maintainability — what they share is that none of them shows up in a single-node 8-card smoke test.

① new_group 要求所有 rank 都参与,不能提前 break① Every rank must enter new_group — no early break

建组的循环里写一句 break(找到自己所属的组就退出)看着很自然,也确实省了几次无谓的调用 —— 但这违反了 dist.new_group 的契约:全局所有进程都必须进入,哪怕自己不是这个组的成员。原因是 PyTorch 在函数末尾会做一次基于 store 的全局屏障,少一个进程就凑不齐。提前 break 意味着靠前的 rank 比靠后的少调了几次:Writing a break into the group-creation loop — stop once you find the group you belong to — looks natural and does skip a few pointless calls. But it violates dist.new_group's contract: every process in the global world must enter it, member or not. PyTorch ends the call with a store-based barrier, and one absentee is enough to stall it. An early break means the lower ranks call it fewer times than the higher ones:

② 建组要用全局 rank,不能用 LOCAL_RANK② Build groups from the global rank, not LOCAL_RANK

分组时取 rank 有两个来源,os.environ['LOCAL_RANK'] 和 dist.get_rank(),单机下它们的值恰好相同,所以随手拿哪个都能跑通。但通信域是全局概念,必须用后者:上到两机 16 卡时,两台机器的 LOCAL_RANK 都是 0–7,于是两边会各自认为自己属于同一批组,SP 组的划分直接错位,而 new_group 传的 ranks 列表又是全局编号 —— 两套编号一混,通信对不上。凡是 rank 参与通信域映射的地方,一律用 dist.get_rank();LOCAL_RANK 只该用来 set_device。There are two places to get a rank when partitioning, os.environ['LOCAL_RANK'] and dist.get_rank(), and on a single node they happen to be equal, so either one runs. But a communication domain is a global notion and needs the latter: move to two nodes and 16 cards and both machines see LOCAL_RANK 0–7, so each believes it belongs to the same set of groups while the ranks list handed to new_group is in global numbering. Mix the two numbering schemes and the communication does not line up. Anywhere a rank maps to a communication domain, use dist.get_rank(); reserve LOCAL_RANK for set_device.

③ Sampler 的 __len__ 要按 SP 组数算③ The sampler's __len__ counts SP groups, not cards

开了 SP 之后,数据要按组而不是按卡分发:同一个 SP 组里的卡必须拿到同一个样本序号,否则它们切的根本不是同一条序列。__iter__ 这样写通常不会错,容易漏的是 __len__ —— 它的除数应该是 SP 组的数量 world_size // sp_size,而不是卡数,也不能写死。举个具体的数:8 卡 SP=2 有 4 个组,数据集 1233 条时每张卡实际产出 ceil(1233/4) = 309 条;要是除数写成了 2,__len__ 就会报 617,差一倍。这个值会一路影响 epoch 长度、进度条和学习率调度器的总步数,而且因为 __iter__ 是对的,训练照跑不误,只是所有和「步数」相关的东西都错了。With SP on, data is distributed per group rather than per card: cards in one SP group must receive the same sample index, or they are not slicing the same sequence at all. Writing __iter__ that way is usually straightforward; __len__ is the one people miss — its divisor should be the number of SP groups, world_size // sp_size, not the card count, and certainly not a constant. Concretely: 8 cards at SP=2 gives 4 groups, so on a 1233-sample dataset each card really yields ceil(1233/4) = 309; a divisor of 2 would report 617, off by a factor of two. That number propagates into epoch length, the progress bar and the LR scheduler's total step count — and because __iter__ is fine, training runs happily while everything step-related is wrong.

④ 通信组在 setup 阶段建好,不要拖到 training_step④ Build the group at setup, not inside training_step

建通信组放在第一个 training_step 里是能工作的,但会带来一个连锁反应:SelfAttention.__init__ 执行时通信组还不存在,拿到的 sequence_process_group 只能是 None,于是每次 forward 都得补一句 self.dist_attn.spg = get_sequence_parallel_group() 去打补丁。这不是性能问题,是状态被摊在了两个地方 —— 再叠加 _SEQUENCE_PARALLEL_STATE 这类模块级全局变量,想单测某一层就得先手工把一堆全局状态摆对。把「什么时候建组」和「谁持有这个组」收敛到一个对象里,是后面所有改动的地基,所以参考实现的第 1 步就是它。Creating the group inside the first training_step works, but it sets off a chain reaction: when SelfAttention.__init__ runs the group does not exist yet, so sequence_process_group can only be None, and every forward then has to patch it up with self.dist_attn.spg = get_sequence_parallel_group(). This is not a performance issue but state spread across two places — layer that on top of module-level globals like _SEQUENCE_PARALLEL_STATE and unit-testing a single layer means hand-arranging a pile of global state first. Collapsing "when is the group built" and "who owns it" into one object is the foundation everything else rests on, which is why it is step 1 of the reference implementation.

启动脚本本身也有两处值得进 checklist。一是 source .../set_env.sh 这类环境初始化路径,调试时很容易临时改成本机绝对路径,提交前要换回仓库里的相对路径,否则别人一跑就找不到 CANN。二是 --output_path:多卡脚本之间容易复制漏掉,漏了权重就静悄悄落到默认目录里,训到一半才发现。The launcher script deserves two checklist entries of its own. One is the source .../set_env.sh environment path: during debugging it is easy to point it at a local absolute path, and it needs to go back to the repo-relative one before committing, or nobody else can find CANN. The other is --output_path: it is easy to drop when copying between multi-card scripts, and without it checkpoints land quietly in the default directory — usually noticed halfway through a run.

八、参考实现:五个步骤8 · Reference implementation: five steps

把前面几节的结论拼起来,就是下面这五步。它们彼此独立,可以按顺序落地,每一步做完都能单独验证。整体思路仍然是 Ulysses —— 把隐式状态收敛成一个显式对象,把不必要的通信摘掉,把梯度缩放放到覆盖全部参数的位置,再把约束写成启动时就报错的断言。Putting the previous sections together yields these five steps. They are independent, can be landed in order, and each is verifiable on its own. The approach is still Ulysses — collapse the implicit state into one explicit object, drop the communication that is not needed, move the gradient scaling somewhere that covers every parameter, and turn the constraints into assertions that fire at startup.

第 1 步:把通信域做成一个对象,在 setup 阶段建好Step 1: make the comm domain an object, built at setup

Construct as SelfAttention(dim, heads, sp=ctx) so DistributedAttention gets a real group in __init__, and the patch-up assignment in forward can go.

第 2 步:交叉注意力走本地,不进 all-to-allStep 2: keep cross-attention local, out of the all-to-all

def forward(self, x, y):
    # 文本上下文:每张卡都持有完整的一份,从未被切过

    # 512 被拼成 512*sp(同一份文本复制 sp 遍)。数值等价

    k = self.norm_k(self.k(ctx_kv))  # unsharded -> [b, 512, dim]

第 3 步:梯度缩放只做一次,做在 loss 上Step 3: scale the gradient once, on the loss

与其在两个 autograd 边界上一乘一除、还只覆盖到中间那段,不如把补偿放到唯一一个对所有参数一视同仁的地方:Rather than multiplying at one autograd boundary and dividing at another — covering only what lies between them — put the compensation in the one place that treats every parameter alike:

x = gather_along_seq(x, sp)     # backward: split,不缩放

#   只有 world_size/sp 个,所以整体小了 sp 倍。在 loss 上
#   乘回来,主干和 head/patchify 就拿到同一个尺度。

#   only world_size/sp distinct samples, so the gradient comes out
#   sp times too small. Multiply it back on the loss and backbone,

这样 SP 度对有效学习率就是完全中性的:改 SP 不需要跟着调 lr,不同 SP 度的实验可以直接对比。This makes the SP degree entirely neutral with respect to effective learning rate: change SP without retuning lr, and runs at different SP degrees stay directly comparable.

第 4 步:Sampler 按组数算长度,并支持 shuffleStep 4: size the sampler by group count, and support shuffle

class SPSampler(Sampler):
    """同一 SP 组内的所有 rank 必须拿到同一个样本序号。"""

    def __init__(self, dataset, sp_ctx, shuffle=True, seed=0):
        self.n, self.sp = len(dataset), sp_ctx
        self.shuffle, self.seed, self.epoch = shuffle, seed, 0

    def __iter__(self):
        idx = list(range(self.n))
        if self.shuffle:
            # 同一个 seed:SP 组内各 rank 打乱结果一致,
            # 组间才会拿到不同样本。有了这条保证,就不必
            # 为了安全而整个禁掉 shuffle。
            g = torch.Generator()
            g.manual_seed(self.seed + self.epoch)
            perm = torch.randperm(self.n, generator=g).tolist()
            idx = [idx[i] for i in perm]
        return iter(idx[self.sp.dp_rank :: self.sp.dp_size])

    def __len__(self):
        # 分母是 SP 组的数量(world/sp),不是卡数,更不能写死
        return math.ceil(self.n / self.sp.dp_size)class SPSampler(Sampler):
    """Every rank in one SP group must receive the same sample index."""

    def __init__(self, dataset, sp_ctx, shuffle=True, seed=0):
        self.n, self.sp = len(dataset), sp_ctx
        self.shuffle, self.seed, self.epoch = shuffle, seed, 0

    def __iter__(self):
        idx = list(range(self.n))
        if self.shuffle:

            # identically, so only different groups see different
            # samples. With that guarantee there is no need to
            # disable shuffling altogether just to stay safe.

            idx = [idx[i] for i in perm]

    def __len__(self):
        # Divisor = the SP group count (world/sp), not the card
        # count, and never a constant

九、验证清单9 · Verification checklist

序列并行最难受的地方是错了也能跑:loss 照样下降,只是下降得不太对。所以验证必须做等价性对拍,而不是看曲线像不像。下面四项按成本从低到高排,前两项跑一次就能覆盖绝大多数切分类错误:The nasty thing about sequence parallelism is that a wrong implementation still runs: the loss keeps going down, just not quite correctly. Verification therefore has to be an equivalence check, not a glance at whether the curve looks plausible. The four items below are ordered by cost, and the first two catch the large majority of sharding mistakes in a single run:

  • 前向对拍。 固定权重、固定一个 batch、固定 timestep 与 noise 的随机种子,分别用 sp=1 和 sp=2 跑一次前向,比较 noise_pred。bf16 下应该在 1e-2 量级内,fp32 下应该到 1e-5。差得更多就说明切分或 RoPE 对错了位。Forward equivalence. With fixed weights, a fixed batch, and fixed seeds for timestep and noise, run one forward at sp=1 and one at sp=2 and compare noise_pred. In bf16 expect agreement around 1e-2, in fp32 around 1e-5. Anything looser means the sharding or the RoPE offsets are wrong.
  • 梯度对拍。 同样条件下比较各参数的梯度范数,分组看:blocks.*、head.*、patch_embedding.* 分开统计。第六节讲的缩放覆盖范围就是靠这一步看出来的 —— 只看全局范数,会被主干的占比整个盖过去。Gradient equivalence. Under the same conditions compare per-parameter gradient norms, grouped: blocks.*, head.* and patch_embedding.* counted separately. This is what makes section 6's question of scaling coverage visible — a single global norm buries it under the backbone's share.
  • 建组的连通性。 建完 SPContext 立刻在组内 all_reduce 一个小张量,值应该等于 sp_size。这一步花 30 秒,能把上面第 ①、② 条一次性验掉,不用等训练跑起来。Group connectivity. Right after building SPContext, all-reduce a small tensor within the group; the result should equal sp_size. Thirty seconds of work clears details ① and ② in one shot, long before training starts.
  • 多机一定要单独测。 第 ② 条在单机上完全不显形,再怎么冒烟都测不出来。最小复现是 2 机 × 2 卡、sp=2,打印每个 rank 的 (global_rank, dp_rank, sp_rank),肉眼就能看出分组对不对。Test multi-node separately. Detail ② is entirely invisible on one node — no amount of smoke testing will surface it. The minimal reproduction is 2 nodes × 2 cards at sp=2: print each rank's (global_rank, dp_rank, sp_rank) and the partitioning is right or wrong at a glance.

十、要点10 · Takeaways

01
序列并行只需要改注意力Only attention needs to change

切完序列后,LayerNorm / FFN / 残差都逐 token 独立,原封不动就能跑。全部工程量集中在「让注意力看到完整序列」这一件事上 —— 认清这点,SP 的改造面比想象中小得多。Once the sequence is sharded, LayerNorm, FFN and the residual are all token-independent and run untouched. The entire engineering effort concentrates on one thing — letting attention see the whole sequence. Realise that and SP's blast radius is far smaller than it looks.

02
RoPE 必须跟着序列一起切RoPE has to be sharded with the sequence

位置编码和 token 是绑定的。freqs 用同一个函数、同一个 rank 顺序切开,而且要在 all-to-all 之前施加。这一步错了模型照样收敛,只是位置信息被打乱,很难从 loss 曲线上看出来。Positional encoding is bound to tokens. Shard freqs with the same function and the same rank ordering, and apply it before the all-to-all. Get this wrong and the model still converges — just with scrambled positions, which the loss curve will not tell you.

03
上下文没被切,就别送进 all-to-allDon't all-to-all what was never sharded

交叉注意力的 k/v 每卡都完整,直接本地算就对。顺手交给 DistributedAttention 会把它复制 sp 遍 —— 数值等价所以不报错,却占掉三分之一的 SP 通信量。判断标准是「这个张量被切过吗」,不是「它是不是 q/k/v」。Cross-attention's k/v are complete on every card, so computing locally is correct. Handing them to DistributedAttention out of habit duplicates them sp times — numerically equivalent, so nothing errors, yet it eats a third of the SP traffic. The test is "was this tensor ever sharded", not "is it a q/k/v".

04
梯度缩放要放在覆盖全部参数的地方Scale gradients where all parameters are covered

在两个 autograd 边界上一乘一除,只覆盖夹在中间的那段。放到 loss 上做一次,主干和 head 才拿到同一个尺度,SP 度对学习率也就中性了。Multiplying at one autograd boundary and dividing at another only covers what lies between them. Do it once on the loss and the backbone and the head share one scale, leaving the SP degree neutral with respect to learning rate.

05
集合通信的建组契约不能打折The group-creation contract admits no shortcuts

new_group 要求所有进程都进入,非成员也不例外。「找到自己的组就 break」看着是优化,实际让屏障凑不齐人。这类 bug 不会报错,只会挂住。new_group requires every process to enter it, non-members included. "Break once you find your own group" looks like an optimisation but leaves the barrier short of participants. Bugs of this kind do not raise — they hang.

06
单机能跑不等于多机能跑Working on one node says nothing about many

LOCAL_RANK 在单机上恰好等于全局 rank,于是分组的错误被完全掩盖。凡是涉及 rank 到通信域映射的代码,最小验证配置就得是两机。LOCAL_RANK happens to equal the global rank on one node, which hides the partitioning error completely. Any code mapping ranks to communication domains needs two nodes as its minimum test configuration.

选 SP 方案先看拓扑,再看 head 数Pick an SP scheme by topology first, head count second

Ulysses 的两条硬约束是「SP 组不跨节点」和「num_heads % sp == 0」。前者决定方案成不成立 —— 每层 8 次全连接通信走 IB 必塌;后者决定 SP 度能开多大。两条都满足,再谈实现细节。Ulysses has two hard constraints: an SP group must not span nodes, and num_heads % sp == 0. The first decides whether the scheme is viable at all — eight fully connected collectives per layer over IB will collapse; the second caps how far the SP degree can go. Satisfy both before discussing implementation.

方案对应的代码在 msit / eco-contrib 仓库中 Wan2.1 NPU 适配版的 wan/acceleration/parallel_states.py、diffsynth/models/wan_video_dit.py 与 examples/wanvideo/train_wan_i2v.py;模型规格取自同文件的 14B 配置(dim 5120 / 40 heads / 40 层)。文中通信量与显存均由张量形状推算,未在 NPU 上实测;第七节四条工程细节以最小复现脚本核对过逻辑,未在真实集群上验证时序。The code behind this write-up lives in the Wan2.1 NPU port inside msit / eco-contrib — wan/acceleration/parallel_states.py, diffsynth/models/wan_video_dit.py and examples/wanvideo/train_wan_i2v.py; model dimensions come from the 14B config in the same file (dim 5120 / 40 heads / 40 layers). Communication and memory figures here are derived from tensor shapes and were not measured on NPU; the four engineering details in section 7 were checked for logic with a minimal reproduction, not for timing on a real cluster.
