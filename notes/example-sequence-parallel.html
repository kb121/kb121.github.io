Wan2.1 长序列并行适配方案Adapting Wan2.1 for Long-Sequence Parallelism

分析对象是昇腾生态贡献仓 msit / eco-contrib 里 Wan2.1 的 NPU 适配版,入口脚本 scripts/train_i2v_full_14B_sp2_8p.sh —— 14B 图生视频模型,单机 8 卡,SP=2。它给了同一个模型的两条路:不开 SP 要 两机 32 卡,开 SP 后 单机 8 卡。这篇先把这条路怎么走通的读明白,再把我读出来的四个问题和一版重写方案写下来。The subject is the NPU port of Wan2.1 in Ascend's msit / eco-contrib repository, entry script scripts/train_i2v_full_14B_sp2_8p.sh — a 14B image-to-video model on one node of 8 cards with SP=2. The repo ships two paths for the same model: 32 cards across two nodes without SP, 8 cards on one node with it. This note works out how that path is made to work, then writes down four problems I found in it and a plan for rewriting it.

一、只有三个改动点1 · Only three touch points

序列并行听起来要动整个模型,实际落到代码里只有三处。把这三处认出来,剩下的都是细节:Sequence parallelism sounds like it touches the whole model; in the code it is three places. Recognise those three and the rest is detail:

改动点Touch point 位置Where 做什么What it does
① 通信域① Comm group wan/acceleration/parallel_states.py 把 8 张卡按连续 rank 切成 4 个 SP 组,每组 2 张Carves the 8 cards into 4 SP groups of 2, by contiguous rank
② 切分 / 恢复② Split / gather wan_video_dit.py · 主干 forwardbackbone forward 进 blocks 前沿 seq 维切开,出 blocks 后 all-gather 拼回Shards along seq before the blocks, all-gathers back after them
③ 注意力③ Attention SelfAttention / CrossAttention 换成 DeepSpeed 的 DistributedAttention(Ulysses)Swapped for DeepSpeed's DistributedAttention (Ulysses)

为什么必须动注意力?因为切完序列之后,除注意力以外的所有算子都不受影响。LayerNorm、FFN、残差都是沿 hidden 维逐 token 独立计算的,每张卡拿着自己那半段序列照算就行。只有注意力需要「看到全部 token」—— 这是序列并行唯一真正的难点,也是 Ulysses 要解决的。Why must attention change? Because once the sequence is sharded, every operator except attention is unaffected. LayerNorm, FFN and the residual all work token-by-token along the hidden dimension, so each card computes on its own half of the sequence. Only attention needs to see all tokens — that is the single real difficulty in sequence parallelism, and what Ulysses exists to solve.

二、形状账:32,760 是怎么来的2 · Shapes: where 32,760 comes from

代码注释里到处是 [1, 32760, 5120]。这个数不是随手写的,它决定了后面所有通信量:The code comments are full of [1, 32760, 5120]. That number is not arbitrary — it sets every communication volume below:

81 帧 → VAE 时间轴 4× 下采样 → 21 个 latent 帧
480×832 → VAE 空间 8× → 60×104 → patch (1,2,2) → 30×52
21 × 30 × 52 = 32,760 token  ·  dim 5120 · 40 heads · head_dim 128 · 40 层81 frames → VAE 4× temporal downsample → 21 latent frames
480×832 → VAE 8× spatial → 60×104 → patch (1,2,2) → 30×52
21 × 30 × 52 = 32,760 tokens  ·  dim 5120 · 40 heads · head_dim 128 · 40 layers

于是有一个贯穿全文的锚:一份完整的激活张量 = 32,760 × 5,120 × 2 B = 320 MiB。DiT 有 40 层,开了梯度重计算也要在每层边界存一份,单卡就是 12.5 GiB。SP=2 把它砍到 6.25 GiB —— 这是序列并行省显存的主体部分。That gives one anchor for the whole note: one full activation tensor = 32,760 × 5,120 × 2 B = 320 MiB. With 40 DiT layers, even under gradient checkpointing one copy is kept at each layer boundary, so 12.5 GiB per card. SP=2 halves that to 6.25 GiB — the bulk of what sequence parallelism saves.

为什么不能靠加卡解决? 加 DP 卡摊薄的是 batch,不是序列。这里 batch_size=1 已经到底了,单个样本的激活就是 12.5 GiB,再加多少张卡它都不变。要让单卡激活下降,只能切序列 —— 这是 SP 存在的全部理由。Why not just add cards? Adding DP ranks thins out the batch, not the sequence. Here batch_size=1 is already the floor, and one sample's activations are 12.5 GiB no matter how many cards you add. The only way to shrink per-card activations is to shard the sequence — which is the entire reason SP exists.

两个细节值得指出。第一,freqs 跟着一起切 —— RoPE 是位置相关的,每张卡必须拿到自己那段 token 对应的频率,否则位置编码会错位。第二,rope 在 all-to-all 之前施加,也就是在「按序列切」的布局下做,这是对的:每张卡知道自己持有哪些位置。Two details worth pointing out. First, freqs is sharded along with it — RoPE is positional, so each card must get the frequencies for its own token range or the positional encoding will be misaligned. Second, RoPE is applied before the all-to-all, that is, in the sequence-sharded layout — which is correct, since each card knows which positions it holds.

四、Ulysses:靠两次转置把注意力变回本地计算4 · Ulysses: two transposes turn attention back into a local computation

Ulysses 的想法很干脆:注意力需要完整序列,那就在算注意力的那一刻把布局换过来。平时每卡持有「一段序列 × 全部 head」,进注意力前用一次 all-to-all 转成「完整序列 × 一部分 head」,算完再转回去。转置之后每张卡手里是完整序列,注意力就退化成一次普通的本地 SDPA,一行都不用改。Ulysses' idea is blunt: attention needs the full sequence, so change the layout at the moment attention runs. Normally each card holds "a slice of the sequence × all heads"; one all-to-all before attention flips it to "the full sequence × a subset of heads", and another flips it back afterwards. After the transpose each card holds a complete sequence, so attention degenerates into an ordinary local SDPA — not a line of it needs changing.

代码里这件事是交给 DeepSpeed 现成的封装做的,自己只提供一个「本地注意力」函数:In the code this is delegated to DeepSpeed's existing wrapper, with only a "local attention" function supplied: 

def flash_attention_sequence_parallelism(q, k, v, compatibility_mode=False):

self.dist_attn = DistributedAttention(

DistributedAttention runs one all-to-all each for q, k and v, plus one on the output — 4 all-to-alls per attention. Self-attention and cross-attention each get a set, so 8 per layer.

五、通信量账本:交叉注意力占了三分之一,而且是白做的5 · The communication bill: cross-attention is a third of it, and it is wasted

一次 all-to-all 每张卡收发本地张量的 (sp−1)/sp。把上面的 320 MiB 锚代进去就能把这一层的账算完:One all-to-all moves (sp−1)/sp of the local tensor per card. Substituting the 320 MiB anchor closes the books on one layer:

交叉注意力那一条格外刺眼,因为它一个字节都不需要传。交叉注意力的 q 来自被切开的视频 latent,k / v 来自文本上下文 —— 而文本上下文在每张卡上都是完整的一份 512 token,从来没被切过。既然 k / v 已经齐全,每张卡拿自己那段 q 直接做本地注意力就是正确答案,不需要任何通信。The cross-attention row stands out because it does not need to move a single byte. Cross-attention's q comes from the sharded video latents, while k and v come from the text context — and the text context is a complete 512-token copy on every card, never sharded. Since k and v are already whole, each card computing local attention between its own q slice and the full k/v is the right answer, with no communication at all.

现在的写法把 k / v 也送进了 all-to-all,于是 512 长度的上下文被沿 seq 维拼接成 512×sp,也就是同一份文本被复制了 sp 遍。有意思的是这不影响正确性:softmax 对重复的 key 会把权重均分,加权和与不复制时逐位相等 —— 我拿一组随机数验过,差值是 0。所以这是纯粹的浪费,不是 bug。The current code sends k and v through the all-to-all too, so the 512-token context gets concatenated along seq into 512×sp — the same text duplicated sp times. The interesting part is that this does not affect correctness: softmax splits the weight evenly across duplicated keys, and the weighted sum comes out bit-identical to the undulplicated case. I checked it on random values and the difference was exactly 0. So it is pure waste, not a bug.

同一个文件里已经有正确写法。 I2V 分支处理图像条件 k_img / v_img 时,用的就是不带任何通信的本地 flash_attention,拿的正是切开后的 q。文本那一路照抄这个写法即可。The correct pattern already exists in the same file. In the I2V branch, the image-condition path k_img / v_img uses a plain local flash_attention with no communication at all, on exactly the sharded q. The text path can simply copy it.

六、梯度怎么对齐:grad_scale 的不对称6 · Aligning gradients: the asymmetry in grad_scale

这是这份实现里最微妙的部分。一个 SP 组里的 2 张卡跑的是同一个样本的不同片段,它们的参数梯度应该相加;而 DeepSpeed 不知道这件事,它把全部 8 张卡的梯度取平均。8 张卡实际只对应 4 个独立样本,于是梯度整体小了 2 倍。This is the subtlest part of the implementation. The two cards in an SP group process different slices of the same sample, so their parameter gradients should be summed. DeepSpeed does not know this and averages across all 8 cards. Those 8 cards correspond to only 4 distinct samples, so the gradient comes out 2× too small.

代码用两个 grad_scale 去补:恢复那一侧反向时 mul_(sp),切分那一侧反向时 div_(sp)。问题在于这两者的作用范围不一样:The code compensates with two grad_scale settings: the gather side does mul_(sp) on its backward, the split side does div_(sp). The trouble is that the two have different reach:

loss → head → recover(×sp) → 40 个 DiT block → prepare(÷sp) → patchify
 
SP 区内部(40 个 block 的权重): ×sp
SP 区外部(head、patch_embedding): ×sp 再 ÷sp = ×1loss → head → recover(×sp) → 40 DiT blocks → prepare(÷sp) → patchify
 
Inside the SP region (the 40 blocks' weights): ×sp
Outside it (head, patch_embedding): ×sp then ÷sp = ×1

也就是说,DiT 主干拿到了补偿,而输入投影和输出头没有,两者之间差了一个 sp 倍的有效学习率。对 SP=2 就是 2 倍。这不会让训练崩掉 —— 参数量上主干占绝对多数,而且 patch_embedding 和 head 本身也在学 —— 但它是一个隐式的、随 SP 度变化的超参偏移:换个 SP 度,这两部分的相对学习率就变了,复现实验时很难查。In other words, the DiT backbone gets the compensation and the input projection and output head do not, leaving an effective learning-rate gap of sp between them — a factor of 2 at SP=2. This will not blow training up: the backbone dominates the parameter count, and patch_embedding and head still learn. But it is an implicit hyperparameter shift that moves with the SP degree — change SP and the relative learning rate of those two parts changes with it, which is painful to track down when reproducing a run.

七、读出来的四个问题7 · Four problems found

下面四条我都用最小复现脚本核对过。前两条是正确性问题,后两条是工程问题。All four below were checked against a minimal reproduction. The first two are correctness problems; the last two are engineering ones.

① new_group 的调用次数在各 rank 之间不一致① new_group is called a different number of times on different ranks

建组的循环里有一句 break:找到自己所属的组就退出。但 dist.new_group 的契约是全部进程都必须进入,哪怕自己不属于这个组——PyTorch 在函数末尾会做一次基于 store 的全局屏障。提前 break 意味着靠前的 rank 少调了几次:The group-creation loop contains a break: stop once you find the group you belong to. But dist.new_group's contract is that every process must enter it, even ones that will not be members — PyTorch ends the call with a store-based barrier over the global world. Breaking early means the lower ranks call it fewer times:

② 建组用的是 LOCAL_RANK② The group is built from LOCAL_RANK

rank = int(os.environ.get('LOCAL_RANK', 0)) —— 单机上 LOCAL_RANK 恰好等于全局 rank,所以这个脚本能跑。但一旦上到两机 16 卡,两台机器的 LOCAL_RANK 都是 0–7,两边会各自认为自己属于同一批组,SP 组的划分直接错位。这一条是单机脚本能跑、多机静默出错的典型形态。rank = int(os.environ.get('LOCAL_RANK', 0)) — on a single node LOCAL_RANK happens to equal the global rank, which is why this script runs. Move to two nodes and 16 cards, though, and both machines have LOCAL_RANK 0–7, so each believes it belongs to the same set of groups and the SP partitioning is misaligned. This is the classic shape of a bug that works on one node and fails silently on many.

③ Sampler 的 __len__ 把组数写死成 2③ The sampler's __len__ hard-codes the group count to 2

DistributedSequenceParallelismSampler 的 __iter__ 是对的:同一 SP 组里的卡拿到同一个样本序号。但 __len__ 返回的是 (total + 1) // 2,那个 2 是写死的,应该是 SP 组的数量。8 卡 SP=2 有 4 个组,数据集 1233 条时 __iter__ 实际产出 309 条,__len__ 却说 617 —— 差一倍。这会直接错报 epoch 长度和进度条,也会和脚本里 --steps_per_epoch 1233 对不上。DistributedSequenceParallelismSampler.__iter__ is correct: cards in the same SP group receive the same sample index. But __len__ returns (total + 1) // 2, where the 2 is hard-coded and should be the number of SP groups. With 8 cards at SP=2 there are 4 groups, so on a 1233-sample dataset __iter__ actually yields 309 while __len__ claims 617 — off by a factor of two. That misreports epoch length and the progress bar, and does not line up with the script's --steps_per_epoch 1233.

④ SP 在第一个 training_step 里才初始化④ SP is initialised inside the first training_step

建通信组这件事发生在 training_step 里,而不是 setup 阶段。后果是 SelfAttention.__init__ 拿到的 sequence_process_group 是 None,于是每次 forward 都要补一句 self.dist_attn.spg = get_sequence_parallel_group() 去打补丁。这不是性能问题,是状态机被摊开在了两个地方 —— 加上 _SEQUENCE_PARALLEL_STATE 这类模块级全局变量,想单测某一层就得先手工把全局状态摆对。Creating the communication group happens in training_step rather than at setup. The consequence is that SelfAttention.__init__ receives None for sequence_process_group, so every forward has to patch it up with self.dist_attn.spg = get_sequence_parallel_group(). This is not a performance issue but a state machine spread across two places — and combined with module-level globals like _SEQUENCE_PARALLEL_STATE, unit-testing a single layer means hand-arranging global state first.

另外两处提交卫生问题:脚本里 source /home/luguansong/CANN/ascend-toolkit/set_env.sh 是个人绝对路径,把仓库里原本正确的那行注释掉了;--output_path 相比 32 卡脚本漏了,权重会落到默认目录。Two hygiene issues as well: the script's source /home/luguansong/CANN/ascend-toolkit/set_env.sh is a personal absolute path that comments out the correct line already in the repo; and --output_path is missing relative to the 32-card script, so checkpoints land in the default directory.

八、实现方案:如果重写一版8 · Implementation plan: if I were rewriting it

思路不变 —— Ulysses 对这个模型是对的选择:序列 32K 但 head 有 40 个,通信量随 SP 递减,而且注意力实现完全不用改。要改的是把隐式状态收敛成显式对象,把白做的通信去掉,把梯度缩放摆到明处。The approach stays — Ulysses is the right choice for this model: a 32K sequence with 40 heads to go around, communication that falls as SP grows, and no change needed to the attention kernel itself. What changes is collapsing implicit state into an explicit object, removing the wasted communication, and putting the gradient scaling out in the open.

第 1 步:把通信域做成一个对象,在 setup 阶段建好Step 1: make the comm domain an object, built at setup

class SPContext:
    """一次建好,之后只读。替代散落的模块级全局变量。"""

    def __init__(self, sp_size: int):
        assert dist.is_initialized(), "先 init_process_group 再建 SPContext"
        world = dist.get_world_size()
        rank = dist.get_rank()                      # 全局 rank,不是 LOCAL_RANK
        assert world % sp_size == 0, f"world({world}) 必须被 sp_size({sp_size}) 整除"

        self.sp_size = sp_size
        self.dp_size = world // sp_size
        self.group = None

        # 关键:所有 rank 都要走完整个循环,不能提前 break。
        # new_group 末尾有一次全局屏障,少一个进程就凑不齐。
        for i in range(self.dp_size):
            ranks = list(range(i * sp_size, (i + 1) * sp_size))
            g = dist.new_group(ranks)               # 每个 rank 都调 dp_size 次
            if rank in ranks:
                self.group = g
                self.sp_rank = rank - i * sp_size
                self.dp_rank = i
        assert self.group is not None

    @property
    def enabled(self) -> bool:
        return self.sp_size > 1class SPContext:
    """Built once, read-only thereafter. Replaces the scattered module-level globals."""

    def __init__(self, sp_size: int):
        assert dist.is_initialized(), "init_process_group before constructing SPContext"
        world = dist.get_world_size()
        rank = dist.get_rank()                      # the global rank, not LOCAL_RANK
        assert world % sp_size == 0, f"world({world}) must be divisible by sp_size({sp_size})"

        self.sp_size = sp_size
        self.dp_size = world // sp_size
        self.group = None

        # The point: every rank must walk the whole loop; no early break.
        # new_group ends in a global barrier, and one absent process stalls it.
        for i in range(self.dp_size):
            ranks = list(range(i * sp_size, (i + 1) * sp_size))
            g = dist.new_group(ranks)               # every rank calls it dp_size times
            if rank in ranks:
                self.group = g
                self.sp_rank = rank - i * sp_size
                self.dp_rank = i
        assert self.group is not None

    @property
    def enabled(self) -> bool:
        return self.sp_size > 1

建好之后随模型一起传下去,而不是靠全局变量取。SelfAttention(dim, heads, sp=ctx) 这样构造,DistributedAttention 在 __init__ 里就能拿到真的 group,forward 里那句打补丁的赋值可以删掉。Once built, pass it down with the model instead of fetching it from a global. Construct as SelfAttention(dim, heads, sp=ctx) so DistributedAttention gets a real group in __init__, and the patch-up assignment in forward can go.

    ctx_kv = y[:, 257:] if self.has_image_input else y   # text context, complete on every card
    q = self.norm_q(self.q(x))                           # q was sharded along seq -> [b, s/sp, dim]
    k = self.norm_k(self.k(ctx_kv))                      # k/v were never sharded -> [b, 512, dim]
    v = self.v(ctx_kv)

    # k/v are already whole and q is merely missing some tokens — computing
    # locally IS the right answer, with no communication at all.
    # The original sends k/v through the all-to-all too, concatenating 512 into
    # 512*sp (the same text duplicated sp times). Numerically equivalent —
    # softmax splits the weight evenly across duplicated keys — but two
    # round trips wasted.
    x = flash_attention(q, k, v, num_heads=self.num_heads)

按动图 2 的账,这一步在 SP=2 下砍掉约 34% 的 SP 通信量,而且 SP 越大占比越高。改动只有几行,风险极低 —— 因为同文件的图像条件分支已经是这个写法。By Figure 2's arithmetic this removes about 34% of SP communication at SP=2, and a larger share as SP grows. It is a few lines and very low risk, since the image-condition branch in the same file already works this way.

第 3 步:梯度缩放只做一次,做在 loss 上Step 3: scale the gradient once, on the loss

与其在两个 autograd 边界上一乘一除、还只覆盖到中间那段,不如把补偿放到唯一一个对所有参数一视同仁的地方:Rather than multiplying at one autograd boundary and dividing at another — covering only what lies between them — put the compensation in the one place that treats every parameter alike: 

# 切分/恢复两侧都用 grad_scale=None,让它们成为纯粹的数据搬运
x = split_along_seq(x, sp)      # backward: all_gather,不缩放
x = gather_along_seq(x, sp)     # backward: split,不缩放

# 补偿只在这里做一次:
#   DeepSpeed 会对全部 world_size 张卡取平均,但独立样本只有 world_size/sp 个,
#   所以整体小了 sp 倍 —— 在 loss 上乘回来,主干和 head/patchify 拿到同一个尺度。
loss = mse_loss(pred, target) * self.scheduler.training_weight(t)
if sp_ctx.enabled:
    loss = loss * sp_ctx.sp_size# Both sides use grad_scale=None, making them pure data movement
x = split_along_seq(x, sp)      # backward: all_gather, unscaled
x = gather_along_seq(x, sp)     # backward: split, unscaled

# Compensate exactly once, here:
#   DeepSpeed averages over all world_size cards, but there are only
#   world_size/sp distinct samples, so the gradient is sp times too small.
#   Multiply it back on the loss and the backbone, head and patchify all
#   share one scale.
loss = mse_loss(pred, target) * self.scheduler.training_weight(t)
if sp_ctx.enabled:
    loss = loss * sp_ctx.sp_size

这样 SP 度对有效学习率就是完全中性的:改 SP 不需要跟着调 lr,不同 SP 度的实验可以直接对比。This makes the SP degree entirely neutral with respect to effective learning rate: change SP without retuning lr, and runs at different SP degrees stay directly comparable.

第 4 步:Sampler 按组数算长度,并支持 shuffleStep 4: size the sampler by group count, and support shuffle

class SPSampler(Sampler):
    """同一 SP 组内的所有 rank 必须拿到同一个样本序号。"""

    def __init__(self, dataset, sp_ctx, shuffle=True, seed=0):
        self.n, self.sp = len(dataset), sp_ctx
        self.shuffle, self.seed, self.epoch = shuffle, seed, 0

    def __iter__(self):
        idx = list(range(self.n))
        if self.shuffle:
            # 用同一个 seed:SP 组内各 rank 打乱结果一致,组间才会拿到不同样本。
            # 原实现禁掉 shuffle,其实只要种子一致就没有问题。
            g = torch.Generator(); g.manual_seed(self.seed + self.epoch)
            idx = [idx[i] for i in torch.randperm(self.n, generator=g).tolist()]
        return iter(idx[self.sp.dp_rank :: self.sp.dp_size])

    """Every rank in one SP group must receive the same sample index."""

        self.n, self.sp = len(dataset), sp_ctx
        self.shuffle, self.seed, self.epoch = shuffle, seed, 0

    def __iter__(self):
        idx = list(range(self.n))
        if self.shuffle:
            # One shared seed: ranks inside an SP group shuffle identically, so
            # only different groups see different samples. The original disables
            # shuffle entirely, which a consistent seed makes unnecessary.
            g = torch.Generator(); g.manual_seed(self.seed + self.epoch)
            idx = [idx[i] for i in torch.randperm(self.n, generator=g).tolist()]
        return iter(idx[self.sp.dp_rank :: self.sp.dp_size])

    def __len__(self):
        # The original hard-codes //2; the correct divisor is the SP group count
        return math.ceil(self.n / self.sp.dp_size)

第 5 步:把约束写成启动时的断言Step 5: turn the constraints into startup assertions

Ulysses 有几条硬约束,现在散落在注释里。它们应该在建 SPContext 时就报错,而不是等到第一个 step 挂掉:Ulysses has a few hard constraints, currently scattered through comments. They should fail at SPContext construction rather than at the first step:

约束Constraint 这个模型This model 违反了会怎样If violated
world_size % sp == 0 8 % 2 ✓ 有卡分不进组Some cards land in no group
num_heads % sp == 0 40 % 2 ✓  上限 40cap 40 all-to-all 散不开 head 维The all-to-all cannot scatter the head dim

最后一条最容易被忽略,也最贵。all-to-all 是全连接、挡在计算路径上、每层 8 次 —— 这类通信必须待在节点内的高带宽域里。通信量账本那篇按量级排过序,交互形态那篇讲的就是为什么「能不能重叠」比「传多少」更决定扩展性。The last one is the easiest to overlook and the most expensive. An all-to-all is fully connected, sits on the critical path, and happens 8 times per layer — that class of communication has to stay inside the node's high-bandwidth domain. The communication ledger ranks these by magnitude, and the interaction note is about why "can it overlap" predicts scalability better than "how much it sends".

九、怎么验证改对了9 · How to verify the rewrite

序列并行最难受的地方是错了也能跑:loss 会下降,只是下降得不太对。所以验证必须做等价性对拍,而不是看曲线像不像:The nasty thing about sequence parallelism is that a wrong implementation still runs: the loss goes down, just not quite correctly. So verification has to be an equivalence check, not a glance at whether the curve looks plausible:

  • 前向对拍。 固定权重、固定一个 batch、固定 timestep 与 noise 的随机种子,分别用 sp=1 和 sp=2 跑一次前向,比较 noise_pred。bf16 下应该在 1e-2 量级内,fp32 下应该到 1e-5。差得更多就说明切分或 RoPE 对错了位。Forward equivalence. With fixed weights, a fixed batch, and fixed seeds for timestep and noise, run one forward at sp=1 and one at sp=2 and compare noise_pred. In bf16 expect agreement around 1e-2, in fp32 around 1e-5. Anything looser means the sharding or the RoPE offsets are wrong.
  • 梯度对拍。 同样条件下比较各参数的梯度范数,分组看:blocks.*、head.*、patch_embedding.* 分开统计。第六节那个不对称就是靠这一步暴露出来的 —— 只看全局范数会被主干的占比盖过去。Gradient equivalence. Under the same conditions compare per-parameter gradient norms, grouped: blocks.*, head.* and patch_embedding.* counted separately. That is exactly how the asymmetry in section 6 surfaces — a single global norm hides it behind the backbone's share.
  • 建组的连通性。 建完 SPContext 立刻在组内跑一次 all_reduce 小张量,值应该等于 sp_size。这一步能在 30 秒内暴露上面第 ①、② 条,不用等训练跑起来。Group connectivity. Right after building SPContext, all-reduce a small tensor within the group; the result should equal sp_size. This surfaces problems ① and ② above within 30 seconds, long before training starts.
  • 多机一定要单独测。 第 ② 条在单机上完全不显形。最小复现是 2 机 × 2 卡、sp=2,打印每个 rank 的 (global_rank, dp_rank, sp_rank),肉眼就能看出分组对不对。Test multi-node separately. Problem ② is completely invisible on one node. The minimal reproduction is 2 nodes × 2 cards at sp=2: print each rank's (global_rank, dp_rank, sp_rank) and the partitioning is wrong or right at a glance.

十、要点10 · Takeaways

01
序列并行只需要改注意力Only attention needs to change

切完序列后,LayerNorm / FFN / 残差都逐 token 独立,原封不动就能跑。全部工程量集中在「让注意力看到完整序列」这一件事上 —— 认清这点,SP 的改造面比想象中小得多。Once the sequence is sharded, LayerNorm, FFN and the residual are all token-independent and run untouched. The entire engineering effort concentrates on one thing — letting attention see the whole sequence. Realise that and SP's blast radius is far smaller than it looks.

02
RoPE 必须跟着序列一起切RoPE has to be sharded with the sequence

位置编码和 token 是绑定的。freqs 用同一个函数、同一个 rank 顺序切开,而且要在 all-to-all 之前施加。这一步错了模型照样收敛,只是位置信息被打乱,很难从 loss 曲线上看出来。Positional encoding is bound to tokens. Shard freqs with the same function and the same rank ordering, and apply it before the all-to-all. Get this wrong and the model still converges — just with scrambled positions, which the loss curve will not tell you.

03
上下文没被切,就别送进 all-to-allDon't all-to-all what was never sharded

交叉注意力的 k/v 每卡都完整,直接本地算即可。现有写法把它复制了 sp 遍 —— 数值等价所以不报错,但白占了三分之一的 SP 通信量。能跑通不代表没浪费。Cross-attention's k/v are complete on every card, so compute locally. The current code duplicates them sp times — numerically equivalent, so nothing errors, yet it consumes a third of the SP communication. Running correctly is not the same as running efficiently.

04
梯度缩放要放在覆盖全部参数的地方Scale gradients where all parameters are covered

在两个 autograd 边界上一乘一除,只覆盖夹在中间的那段。放到 loss 上做一次,主干和 head 才拿到同一个尺度,SP 度对学习率也就中性了。Multiplying at one autograd boundary and dividing at another only covers what lies between them. Do it once on the loss and the backbone and the head share one scale, leaving the SP degree neutral with respect to learning rate.

05
集合通信的建组契约不能打折The group-creation contract admits no shortcuts

new_group 要求所有进程都进入,非成员也不例外。「找到自己的组就 break」看着是优化,实际让屏障凑不齐人。这类 bug 不会报错,只会挂住。new_group requires every process to enter it, non-members included. "Break once you find your own group" looks like an optimisation but leaves the barrier short of participants. Bugs of this kind do not raise — they hang.

06
单机能跑不等于多机能跑Working on one node says nothing about many

LOCAL_RANK 在单机上恰好等于全局 rank,于是分组的错误被完全掩盖。凡是涉及 rank 到通信域映射的代码,最小验证配置就得是两机。LOCAL_RANK happens to equal the global rank on one node, which hides the partitioning error completely. Any code mapping ranks to communication domains needs two nodes as its minimum test configuration.
