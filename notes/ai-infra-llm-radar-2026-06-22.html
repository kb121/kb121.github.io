历史:从模型训练优化到推理服务优化

早期 AI Infra 的核心矛盾是训练阶段的显存和通信,代表是 DeepSpeed/ZeRO 这类分布式优化库。2023 年后,开源大模型开始从“可训练”转向“可服务”:vLLM 用 PagedAttention 解决 KV cache 碎片化,llama.cpp 把本地推理变成开发者日常工具。这个阶段的评价指标主要是 tokens/s、显存占用、batching 和硬件覆盖。

当下:推理引擎、KV cache、Agent runtime 同时收敛

2026 年 7 月的证据很集中:vLLM 0.25.0 把 MRv2 设为 dense model 默认路径,并明确删除 legacy PagedAttention;SGLang 0.5.15 把 Spec V2、IndexShare MTP、Blackwell NVFP4 优化放在 highlights;DSpark 博客进一步把 speculative decoding 做成按请求动态 verify 预算。这说明 serving engine 已经从“单点 kernel 优化”进入“调度器 + CUDA graph + cost model”的协同优化。

另一个当下变化是 KV cache 的身份变化。LMCache MP mode 的 benchmark 显示平均 TTFT 从 3.98s 降到 0.29s,p99 从 13.55s 降到 1.30s;llm-d 的 FS backend 则把 KV blocks 放入共享文件系统,以换取跨节点复用和更大工作集。也就是说,KV cache 不再只是 GPU 内存管理细节,而是新的“推理数据平面”。

动态图 4:生产推理路径从无状态变成有状态
过去:request 进来,模型算完就结束。现在:request、prefix、tool call、cache hit、storage tier 都影响下一步调度。

未来:四个判断

  1. KV cache 会产品化。 未来的推理平台会像今天的数据库一样管理 KV:容量、命中率、冷热分层、权限、持久化、跨副本一致性和成本都要被暴露。
  2. 推理引擎会继续“内核共享、调度分化”。 FlashInfer 这类 kernel substrate 会被多个 engine 复用;差异化会体现在 scheduler、prefix/tree cache、speculative policy、observability。
  3. Agent Infra 会压迫 serving API。 MCP、coding agents、browser agents、AI gateway 的快速 release 意味着请求不再是单轮 chat completion,而是长链路、多工具、多状态、可回放的 workflow。
  4. 指标会从平均 tokens/s 转向 p99 TTFT、cache hit value 和单位任务成本。 长上下文 Agent 的用户体验受尾延迟和重复 prefill 支配,所以“少算一次”往往比“单步快一点”更值钱。
