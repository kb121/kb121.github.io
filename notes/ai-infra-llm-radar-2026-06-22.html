3. 趋势分析: 历史、当下、未来

3.1 历史: 从“模型服务化”到“agent 操作层”

过去三年 AI Infra 的重心经历了六步:先把模型封成 API,再用 PagedAttention / continuous batching / quantization 提升吞吐,然后把本地量化 runtime 推给开发者,接着把工具调用和 agent state 引入生产,最后在 2026 年把 cache、router、protocol、Kubernetes、capacity isolation 和审计治理推到同一张架构图上。

3.2 当下: 成本瓶颈沿“上下文 → KV → 路由 → 平台”迁移

当下最关键的事实是 agent session 不再像 chat completion 那样短。vLLM x Mooncake 的 Codex/SWE-bench Pro traces 显示 median 33 turns,到第 30 轮上下文约 80K tokens,平均 input-to-output ratio 约 131:1。也就是说,重复读长上下文的 prefill 成本远大于每轮新增 decode,缓存命中率会直接改变系统经济性。

  • 证据 1: Google Cloud 的 Lustre 方案把 95% cache hit rate 与 50%+ TCO saving 绑定,说明长上下文成本主要在可复用前缀。
  • 证据 2: LMCache benchmark 在 Qwen3-8B long-doc QA 中把 mean TTFT 从 757ms 降到 185ms,benchmark duration 从 23.47s 降到 13.79s。
  • 证据 3: vLLM x Mooncake 在 agent traces 中把 cache hit rate 从 1.7% 提到 92.2%,并显著改善 throughput / TTFT / E2E latency。
  • 证据 4: GitHub 5 月 availability report 将流量增长归因于 AI-assisted / agentic workflows,且 Actions、Copilot agent、PR review thread 都出现过相互放大的事故。

3.3 未来: 分层 agent 操作系统会成为 AI Infra 的竞争单元

未来 6-18 个月,单个模型或单个 engine 的优势会被“分层平台能力”重新定价。真正可持续的 AI Infra 会把模型、推理、缓存、协议、调度、治理和成本控制打包成可组合的操作层。这个操作层既要跑 frontier model,也要跑 open-weight/local model;既要支持高吞吐 API,也要支持长时间 agent session;既要快,也要可恢复、可审计、可限流。

  1. 模型层: Frontier model 承接复杂推理,open-weight/local model 承接隐私、低延迟、成本敏感和边缘任务。
  2. 推理层: vLLM / SGLang / TensorRT-LLM / llama.cpp 分别服务云端吞吐、结构化生成、NVIDIA 极致优化和本地可移植。
  3. 缓存层: KV cache 会有配额、压缩、冷热分层、RDMA/NVLink/Lustre/NVMe 通道和 cache-aware routing。
  4. 协议层: MCP stateless 化后,企业会用 gateway、auth、routing header 和 audit log 管理 agent 工具边界。
  5. 调度层: GAIE、llm-d、RBG、Kueue 会让 LLM 的队列、gang scheduling、GPU topology、SLO 进入 Kubernetes 原生语义。
  6. 治理层: prompt/response hash、tool-call audit、sandbox、PII policy、成本归因和回放复现会成为默认生产要求。

4. 一句话结论

2026-07-02 的 AI Infra 雷达显示:最热的不是某个单点模型,而是 agentic pressure 把推理芯片、KV cache、低精度、Kubernetes routing、MCP stateless、cloud cold start 和 GitHub/CI 平台容量连成了一条系统工程主线。过去拼“模型能不能调用”,当下拼“每轮调用贵不贵、稳不稳”;未来拼的是能否把模型、缓存、工具、调度和审计做成可持续的 agent 操作层。
