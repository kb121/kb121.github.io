历史:从模型训练优化到推理服务优化

早期 AI Infra 的核心矛盾是训练阶段的显存和通信,代表是 DeepSpeed/ZeRO 这类分布式优化库。2023 年后,开源大模型开始从“可训练”转向“可服务”:vLLM 用 PagedAttention 解决 KV cache 碎片化,llama.cpp 把本地推理变成开发者日常工具。到 2025 年,OpenAI gpt-oss-120b/20b 这种 single-80GB / 16GB memory target 的 open-weight reasoning model 进一步把“自托管推理、量化格式、工具调用和结构化输出”推到基础设施中心。

当下:推理引擎、KV cache、Agent runtime 同时收敛

2026 年 7-8 月的证据很集中:vLLM 0.26.0 把 Inkling、DeepSeek-V4、per-KV-cache-group attention backend、KV offloading/tiered storage 和 Transformers 5.13 放在同一条 release 主线;SGLang 0.5.16 升级 flashinfer / CuTe DSL / sgl-kernel 并覆盖 Kimi K3 day-0;FlashInfer 0.6.16 与 0.6.17 nightly 继续承担 FP4、MoE、VSA、all-reduce fusion 等 kernel substrate。这说明 serving engine 已经从“单点 kernel 优化”进入“调度器 + kernel substrate + 硬件量化格式 + 模型架构”的协同优化。

另一个当下变化是 KV cache 的身份变化。LMCache 0.5.x 从 P2P KV transfer、HMA、L2 quota/usage/eviction、Cloud Bigtable / object-store 后端,发展到 2026-08-01 的 v0.5.3rc1 CUDA / ROCm wheel 与 nightly。此前 LMCache MP mode benchmark 显示平均 TTFT 从 3.98s 降到 0.29s,p99 从 13.55s 降到 1.30s;llm-d 的 FS backend 则把 KV blocks 放入共享文件系统。也就是说,KV cache 不再只是 GPU 内存管理细节,而是新的“推理数据平面”。

未来:四个判断

  1. KV cache 会产品化。 未来的推理平台会像今天的数据库一样管理 KV:容量、命中率、冷热分层、权限、持久化、跨副本一致性和成本都要被暴露;LMCache 按 CUDA/ROCm/nightly 发布制品就是早期信号。
  2. 推理引擎会继续“内核共享、调度分化”。 FlashInfer 这类 kernel substrate 会被多个 engine 复用;差异化会体现在 scheduler、prefix/tree cache、speculative policy、observability、模型 parser 和硬件拓扑适配。
  3. Agent Infra 会压迫 serving API。 MCP、LangGraph、LiteLLM、coding agents 的快速 release 意味着请求不再是单轮 chat completion,而是长链路、多工具、多状态、可回放、带凭证委托和结果审计的 workflow。
  4. 指标会从平均 tokens/s 转向 p99 TTFT、cache hit value、每任务成本和每瓦 tokens。 长上下文 Agent 的用户体验受尾延迟和重复 prefill 支配;数据中心侧的约束也从“有没有 GPU”扩展到“有没有电、有没有融资、有没有可持续利用率”。
