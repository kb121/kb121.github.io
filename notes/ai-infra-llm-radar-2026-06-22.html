历史:从模型训练优化到推理服务优化

早期 AI Infra 的核心矛盾是训练阶段的显存和通信,代表是 DeepSpeed/ZeRO 这类分布式优化库。2023 年后,开源大模型开始从“可训练”转向“可服务”:vLLM 用 PagedAttention 解决 KV cache 碎片化,llama.cpp 把本地推理变成开发者日常工具。这个阶段的评价指标主要是 tokens/s、显存占用、batching 和硬件覆盖。

当下:推理引擎、KV cache、Agent runtime 同时收敛

2026 年 7 月底的证据很集中:Kimi K3 把 2.8T MoE、1M context、KDA/MLA 混合状态、MXFP4 MoE、DSpark speculative decoding 和 day-0 serving 放进同一周;vLLM 0.26.0 把 Inkling、DeepSeek-V4 performance push、flexible attention backend、KV/offload 改进放在同一条 release 主线;SGLang 0.5.16 删除实验性量化路径,把 NVFP4 GEMM 收敛到 FlashInfer;FlashInfer 0.6.16 nightly/rc 继续修底层 cubin 与架构 build 问题。这说明 serving engine 已经从“单点 kernel 优化”进入“调度器 + kernel substrate + 硬件量化格式 + 模型结构”的协同优化。

另一个当下变化是 KV cache 的身份变化。LMCache v0.5.2 为 vLLM 0.26.0 兼容而发布,并把 CacheBlend、HMA、L2 storage backend 写进 release;Kimi K3 配方又要求 engine 处理 paged KV blocks 与 KDA recurrent-state blocks;vLLM OffloadingConnector / llm-d tiered prefix cache 则把 HBM、CPU RAM、filesystem 和 KV events 放进同一个 offload 层级。也就是说,KV cache 不再只是 GPU 内存管理细节,而是新的“推理数据平面”。

Agent Infra 的变化同样清晰。MCP 2026-07-28 稳定版把协议改成 stateless,让普通 HTTP 基础设施更容易承载工具调用;LiteLLM 1.94.0/1.95.0-rc.1 则把 client-held credentials、gateway-bound envelope、issuer-anchored OAuth discovery、ID-JAG、resource indicators 和防止凭证泄露写进 release。长期运行 Agent 的基础设施问题,已经从“如何调用工具”升级为“如何把工具权限、状态、审计、成本和模型路由做成控制面”。

未来:四个判断

  1. KV cache 会产品化。 未来的推理平台会像今天的数据库一样管理 KV:容量、命中率、冷热分层、权限、持久化、跨副本一致性、事件流和成本都要被暴露。
  2. 推理引擎会继续“内核共享、调度分化”。 FlashInfer 这类 kernel substrate 会被多个 engine 复用;差异化会体现在 scheduler、DCP、prefix/tree cache、speculative policy、observability 和硬件拓扑适配。
  3. Agent Infra 会压迫 serving API。 MCP、LangGraph、LiteLLM、coding agents 的快速 release 意味着请求不再是单轮 chat completion,而是长链路、多工具、多状态、可回放、带凭证委托的 workflow;gateway 必须同时做模型路由、工具授权、审计和成本治理。
  4. 指标会从平均 tokens/s 转向 p99 TTFT、cache hit value、每任务成本和每瓦 tokens。 长上下文 Agent 的用户体验受尾延迟和重复 prefill 支配;数据中心侧的约束也从“有没有 GPU”扩展到“有没有电、有没有融资、有没有可持续利用率”。
