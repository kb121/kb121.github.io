历史:从模型训练优化到推理服务优化

早期 AI Infra 的核心矛盾是训练阶段的显存和通信,代表是 DeepSpeed/ZeRO 这类分布式优化库。2023 年后,开源大模型开始从“可训练”转向“可服务”:vLLM 用 PagedAttention 解决 KV cache 碎片化,llama.cpp 把本地推理变成开发者日常工具。这个阶段的评价指标主要是 tokens/s、显存占用、batching 和硬件覆盖。

当下:推理引擎、KV cache、Agent runtime 同时收敛

2026 年 7 月的证据很集中:vLLM 0.26.0 把 Inkling、DeepSeek-V4 vendor-wide 性能、flexible attention backend、KV offload storage、hybrid KV-cache manager 和 object-store tier 放在同一条 release 主线;SGLang 0.5.16 与 Kimi K3 day-0 支持把 KDA、NoPE-MLA、latent MoE、NVFP4/MXFP4 和 Miles rollout 合并进生产路径;FlashInfer 0.6.16rc3 / 0.6.15 nightly 则把 cubin、SM12x、MoE、MLA、VSA 等能力下沉到 kernel substrate。这说明 serving engine 已经从“单点 kernel 优化”进入“调度器 + kernel substrate + 硬件量化格式 + 模型结构”的协同优化。

另一个当下变化是 KV cache 的身份变化。LMCache v0.5.2 为 vLLM 0.26.0 兼容而发布,并把 CacheBlend under HMA、dual-RoPE/SWA、全局 P2P token matching、Azure Blob/Valkey/Bigtable/HyperPod 等后端写进 release;此前 LMCache MP mode benchmark 显示平均 TTFT 从 3.98s 降到 0.29s,p99 从 13.55s 降到 1.30s;llm-d 的 FS backend 则把 KV blocks 放入共享文件系统。也就是说,KV cache 不再只是 GPU 内存管理细节,而是新的“推理数据平面”。

Agent Infra 同时在补“协议债”。MCP 2026-07-28 稳定规范把无状态生命周期、discovery、subscriptions 和版本化文档推到实现者面前;LiteLLM 1.94.0 继续补 OAuth/DCR/SSO/issuer discovery;LangGraph 1.2.10 把 stream_events 和 projections 类型化。这些证据指向同一件事:Agent 请求不再是单轮 chat completion,而是带版本、凭证、工具发现、状态事件和审计链路的分布式系统调用。

未来:五个判断

  1. KV cache 会产品化。 未来的推理平台会像今天的数据库一样管理 KV:容量、命中率、冷热分层、权限、持久化、跨副本一致性和成本都要被暴露。
  2. 推理引擎会继续“内核共享、调度分化”。 FlashInfer 这类 kernel substrate 会被多个 engine 复用;差异化会体现在 scheduler、prefix/tree cache、speculative policy、observability 和硬件拓扑适配。
  3. Agent Infra 会压迫 serving API。 MCP、LangGraph、LiteLLM、coding agents 的快速 release 意味着请求不再是单轮 chat completion,而是长链路、多工具、多状态、可回放、带凭证委托的 workflow。
  4. 开放权重会把“模型发布”变成“基础设施考试”。 Kimi K3 这类 3T 级开放权重不是下载后即可运行,而是考验 KDA/MLA kernel、MoE 路由、KV 层、量化、rack fabric、显存容量和 API 兼容性。
  5. 指标会从平均 tokens/s 转向 p99 TTFT、cache hit value、每任务成本和每瓦 tokens。 长上下文 Agent 的用户体验受尾延迟和重复 prefill 支配;数据中心侧的约束也从“有没有 GPU”扩展到“有没有电、有没有融资、有没有可持续利用率”。
