AI Infra 与大模型雷达:当天 / 一周 / 一月 / 半年 / 一年热点与趋势

这是一份滚动雷达。统计口径是 2026-07-08 22:00 UTC 附近可查证的信息: GitHub 项目热度取 stars、release、push 时间与项目描述; 新闻/趋势取官方公告、项目 release、云厂商技术博客与行业报道。 结论很清楚:AI Infra 的竞争重心正从“模型参数更大”迁移到“推理系统是否能把昂贵算力持续喂满”。

一眼结论

  • 推理进入“模型代码复用 + 极致后端”阶段。 Hugging Face 7 月 8 日宣布 transformers vLLM backend 对许多架构已达到或超过自定义 vLLM 实现速度,说明模型作者不再必须手写 serving port 才能吃到高性能推理。
  • 跨芯片可移植性能升温。 TechCrunch 7 月 8 日报道 ZML 发布 LLMD,目标是在 NVIDIA、AMD、TPU、Apple Metal、Intel Arc 等硬件上跑开源 LLM,这与 FlashInfer/Triton/CuTeDSL 的 portable kernel 方向同频。
  • agentic workload 开始被单独计量。 NVIDIA/Artificial Analysis 的 AgentPerf 把“每兆瓦并发 agent 数”放进基础设施 benchmark,Blackwell Ultra NVL72 被披露相对 H200 可达 20x agents/MW。
  • KV cache 从优化细节变成分布式系统。 vLLM v0.24、LMCache v0.5.1、SGLang HiCache、Dynamo KVBM 都在围绕 cache placement/transfer/offload/reuse 迭代。
  • agent stack 进入生产约束。 MCP servers 88K+ stars、LangGraph 36K+ stars、browser-use 103K+ stars,再叠加 Otari/GitHub Models 退役,说明模型路由、预算、凭证和治理已经是基础设施问题。

技术趋势:历史、当下、未来

历史:为什么从“训练规模”转向“推理系统”?

早期 LLM 基础设施的中心问题是训练:数据并行、张量并行、ZeRO、checkpoint、模型分发。 但 2023 年以后,应用流量和开源模型让推理成为持续成本中心。vLLM 的 PagedAttention 把 KV cache 管理带进工程主线, llama.cpp/Ollama/Open WebUI 则证明本地推理不是玩具,而是开发者入口。

证据:截至本次统计,Ollama 约 175.7K stars、Open WebUI 约 144.8K、llama.cpp 约 119.7K; 生产推理侧 vLLM 约 85.7K stars, SGLang 约 30.1K stars。热度同时出现在“本地入口”和“生产引擎”,说明这不是单一云厂商趋势。

当下:四个瓶颈决定单位 token 成本

  1. 电力和机房:Anthropic 401MW 租约把容量锁定提前到 2027/2028,AgentPerf 又把“每兆瓦并发 agent”量化,表明电力接入周期和能效会影响模型公司的增长曲线。
  2. 内存和 KV cache:Modular 对 MLSys 2026 的总结指出 KV cache 已成为主导子系统; LMCache/vLLM/SGLang/Dynamo 都在解决 cache 跨层复用。
  3. MoE 通信:Google Cloud A4X + Dynamo 把 WideEP、DeepEP、P/D 解耦和全局 KV cache 管理放进 rack-scale 设计,因为 MoE 的约束已经从单卡算力转到 all-to-all、HBM 和拓扑。
  4. 可移植性能:Hugging Face 的 vLLM backend 与 ZML/LLMD 都在降低“新模型/新硬件接入高性能 serving”的工程成本。
  5. 控制面和治理:GitHub Models 退役、Otari 发布、MCP/LangGraph/browser-use 高热,说明 production LLM app 需要预算、failover、审计、隔离和恢复语义。

未来:我会押注的 6 条技术线

  1. KV cache 会成为“推理数据库”。会出现更明确的 cache schema、生命周期、权限、跨模型复用、热/冷分层和故障恢复。
  2. P/D/E 解耦会标准化。Prefill、Decode、Encode(多模态)会像 web 的 stateless/stateful 服务一样被拆分、独立伸缩和独立定价。
  3. Kubernetes 需要 inference-native API。普通 Service/Ingress 不懂 TTFT、ITL、KV locality、model warmup 和 GPU topology; llm-d/GWIE/KAITO/KServe 会继续补语义。
  4. 硬件异构会倒逼 portable kernels。NVIDIA、AMD、TPU、XPU、CPU/edge 同时存在,Mojo/Triton/CuTeDSL/FlashInfer/MLX/ZML 等抽象会继续抢“可移植性能层”。
  5. agent runtime 会像应用服务器一样标准化。durable execution、sandbox、short-lived credentials、human approval、evals/trace 将成为生产 agent 的默认要求。
  6. 自研推理芯片会继续扩散。模型公司会把模型路线图、kernel、serving SLO 与芯片/网络/内存协同设计,但软件栈必须保留多硬件退路。
  7. 成本治理会前置到开发阶段。模型路由、budget、quota、prompt/cache policy、fallback 和审计不再是平台团队后补,而是应用架构的一部分。
