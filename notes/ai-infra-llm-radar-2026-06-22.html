总判断: 2026 年 7 月初,AI Infra 的主战场已经从“把模型跑起来”迁移到“把模型、cache、router、agent runtime 与开发平台容量组织成稳定操作层”。上层 agent 拉高 PR、CI、工具调用和长上下文需求;下层系统用 vLLM/SGLang、KV cache、FP8/FP4、disaggregated serving、Kubernetes inference routing 和审计治理来吸收压力。

3. 趋势分析: 历史、当下、未来

3.1 历史: 从“能跑模型”到“能服务模型”

2022-2024 的 AI Infra 主线是把 Transformer 变成 API:FlashAttention、PagedAttention、连续批处理、tensor parallel、token streaming、OpenAI-compatible endpoint。TGI、vLLM、TensorRT-LLM、llama.cpp、Ollama 分别从生产服务、吞吐、硬件优化、本地可移植和开发体验切入。到 2025-2026,这些能力被 agent workload 和新模型形态重新组合:MoE、长上下文、MTP、tool-call parsing、多模态、FP4/FP8 让“engine”变成一个持续演进的系统边界。这个阶段的核心指标从单纯 tokens/sec、TTFT、显存占用、batch size 扩展为 端到端任务成功率、cache hit、tool latency、平台隔离和每百万 token 成本。

3.2 当下: Agentic workload 让瓶颈沿链路迁移

当下的核心变化是一次任务不再只是单次 chat completion。Agent 会读文件、检索文档、调用工具、运行测试、写 PR、触发 CI、等待 review,再继续迭代。于是成本和可靠性瓶颈沿着“上下文 → prefill/KV → decode/kernel → 工具协议 → 平台容量 → 审计治理”移动。7 月 5 日的 repo 快照正好印证这一点:同一天活跃的不只是模型 serving engine,还包括 LMCache、llm-d、MCP、LangGraph、OpenAI Agents SDK、Ollama/llama.cpp 和 Model Optimizer。

  • 证据 1: GitHub 5 月可用性报告直接把流量增长归因于 AI-assisted / agentic workflows,并说明 Azure 承载 40% monolith traffic、Git traffic 30%、repository replication 99%。
  • 证据 2: vLLM 0.24.0 的 release note 同时出现 MiniMax-M3、DeepSeek-V4、Streaming Parser Engine、DeepEP v2 和 Rust frontend,说明 serving engine 正在吸收模型、agent 与分布式需求。
  • 证据 3: LMCache 论文和 README 把 KV cache 描述为可持久化、可复用、可观测的 AI-native knowledge,并报告 vLLM+LMCache 在多轮问答/文档分析上最高 15x throughput。
  • 证据 4: TensorRT-LLM 文档把 FP4/FP8、paged KV cache、chunked prefill、LoRA、speculative decoding、disaggregated serving 作为生产特性。
  • 证据 5: GAIE / llm-d / Kueue 说明 Kubernetes 已开始围绕 LLM 的“prefix cache、LoRA affinity、queue depth、TTFT/ITL、SLO”做模型感知调度。

3.3 未来: AI Infra 会变成“分层 agent 操作系统”

未来 6-18 个月的趋势不是某一个 engine 通吃,而是栈分层更清楚:模型层选择能力和成本,推理层压吞吐和延迟,缓存层减少重复 prefill,协议层连接工具和数据,调度层管理 GPU 与 SLO,治理层处理权限、审计和复现。最可能出现的形态是“模型多供应商 + serving 多引擎 + cache/router 独立化 + agent runtime 标准化 + Kubernetes/多云吸收 burst”的组合。

  1. 模型层: frontier model 承接复杂推理,open-weight / local model 承接低延迟、隐私、成本敏感任务;MoE、MTP、长上下文和多模态会继续倒逼 serving 改造。
  2. 推理层: vLLM / SGLang / TensorRT-LLM / llama.cpp 分别服务云端高吞吐、复杂生成、NVIDIA 极致优化和边缘/本地可移植,并在连续批处理、speculative decoding、disaggregated serving 上继续互相吸收。
  3. 缓存层: KV cache 变成可配额、可压缩、可迁移、可观测的共享资源,从“GPU 内状态”升级为“agent memory substrate”。
  4. 协议层: MCP 这类工具协议会像 HTTP/gRPC 之于微服务一样,成为 agent 接入外部世界的标准边界,同时需要权限、审批和审计。
  5. 调度层: Gateway API Inference Extension、llm-d、Kueue 会把 LLM 流量特征带进 Kubernetes 调度,普通 round-robin 会被 prefix/cache/SLO-aware routing 替代。
  6. 治理层: prompt/response hash、tool-call audit、PII 处理、sandbox 隔离、policy enforcement 和可恢复执行会成为企业默认项。

4. 一句话结论

2026 年中期的 AI Infra 关键词是 agentic pressure:agent 把推理成本、上下文复用、低精度硬件、工具协议、Kubernetes 调度、开发平台容量和合规审计同时推到前台。过去拼模型调用,现在拼系统闭环;未来拼的是能否把模型能力稳定、便宜、可恢复、可审计地接入真实工作流。
