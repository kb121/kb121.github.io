AI Infra 与大模型雷达:当天 / 一周 / 一月 / 半年 / 一年热点与趋势

这是一份滚动雷达。统计口径是 2026-07-11 22:00 UTC 附近可查证的信息: GitHub 项目热度取 stars、release、push 时间与项目描述; 新闻/趋势取官方公告、项目 release、云厂商技术博客与行业报道。 今天的核心变化是:AI Infra 的主战场继续从“单模型能力”迁移到“推理软件栈能否把模型、KV cache、spec decode、agent runtime、GPU/CPU/网络/电力协同起来,并把每 token 成本持续压低”。

一眼结论

  • 推理引擎进入“后 PagedAttention”阶段。 vLLM v0.25.0 直接删除 legacy PagedAttention,让 V1/MRv2 backend 成为标准路径,同时把 Model Runner V2 设为 dense model 默认执行路径。
  • vLLM 与 SGLang 的竞争焦点正在收敛到 MoE + spec decode + CUDA Graph。 vLLM v0.25.0 强化 DFlash/DSpark、dynamic speculative decoding、PD disaggregation 和 KV offloading; SGLang v0.5.15 则把 Spec V2、IndexShare MTP、Breakable CUDA Graph、FlashInfer A2A 和 GLM-5.2 NVFP4 生产 serving 放在 headline。
  • “本地/边缘推理”没有降温。 llama.cpp 7 月 11 日发布 b9966,GitHub API 快照显示 120,057 stars 且当天 push; Ollama 175,936 stars、Open WebUI 145,083 stars,说明开源模型的入口仍在本地与自托管工具链。
  • 成本优化开始以系统栈为单位衡量。 NVIDIA 称 Blackwell 上 DeepSeek V4 的 token cost 约一个月内最多降低 5x,组合 disaggregated serving、large expert parallelism、NVFP4 和 multi-token prediction 后 throughput 可达 baseline 的 20x。
  • agent workload 已经改变基础设施指标。 AgentPerf 用 concurrent agents/MW 衡量硬件与软件栈; MCP servers、LangGraph、browser-use、Otari 和 GitHub Models 退役共同指向:agent 不是应用小功能,而是需要 runtime、gateway、budget、tool protocol 和安全边界的工作负载。
  • Kubernetes 正从“能跑 GPU pod”进化为 inference-native 控制面。 KServe v0.19.0、KAITO v0.11.0、llm-d v0.8.1 和 Dynamo v1.2.1 的共同语言是 InferencePool、P/D disaggregation、KV-aware routing、Gateway API、autoscaling 和 SLA planner。

技术趋势:历史、当下、未来

历史:为什么从“训练规模”转向“推理系统”?

早期 LLM 基础设施的中心问题是训练:数据并行、张量并行、ZeRO、checkpoint、模型分发。 但 2023 年以后,应用流量和开源模型让推理成为持续成本中心。vLLM 的 PagedAttention 把 KV cache 管理带进工程主线, llama.cpp/Ollama/Open WebUI 则证明本地推理不是玩具,而是开发者入口。

证据:截至本次统计,Ollama 约 175.9K stars、Open WebUI 约 145.1K、llama.cpp 约 120.1K; 生产推理侧 vLLM 约 86.0K stars, SGLang 约 30.2K stars。热度同时出现在“本地入口”和“生产引擎”,说明这不是单一云厂商趋势。

当下:五个瓶颈决定单位 token 成本

  1. 执行路径和 kernel:vLLM v0.25.0 的 MRv2 默认、PagedAttention 删除、DFlash/DSpark/FlashInfer/FA4/Helion/ROCm/XPU/CPU 优化,说明真正的成本优化来自端到端 execution path,不是单个 attention kernel。
  2. 内存和 KV cache:vLLM 的 KV offloading/PD disaggregation、SGLang HiCache/FlashMLA sparse prefill、LMCache v0.5.1、Dynamo KVBM 都在解决 cache 跨层复用; KV cache 已经像数据库一样需要 placement、tiering、ownership 和恢复语义。
  3. MoE 通信和 spec decode:SGLang 的 FlashInfer A2A、IndexShare MTP、Spec V2,以及 NVIDIA 的 Large EP / NVFP4 / MTP / disaggregated serving 组合,说明 MoE serving 的主矛盾是拓扑、all-to-all、draft token 验证和 memory bandwidth。
  4. agent 控制面:MCP servers、LangGraph、Otari、GitHub Models 退役、AgentPerf 共同说明 production agent 需要预算、failover、工具权限、durable execution、评测和能效指标。
  5. 电力、CPU 和异构硬件:Vera CPU、AgentPerf agents/MW、Anthropic/TeraWulf 401MW 租约、ZML/LLMD 跨芯片推理和 llama.cpp 多平台 release 都在提醒:瓶颈正在从 GPU 卡本身扩展到 rack、CPU、网络、电力和软件可移植层。

未来:我会押注的 7 条技术线

  1. KV cache 会成为“推理数据库”。会出现更明确的 cache schema、生命周期、权限、跨模型复用、热/冷分层和故障恢复。
  2. P/D/E 解耦会标准化。Prefill、Decode、Encode(多模态)会像 web 的 stateless/stateful 服务一样被拆分、独立伸缩和独立定价。
  3. Kubernetes 需要 inference-native API。普通 Service/Ingress 不懂 TTFT、ITL、KV locality、model warmup 和 GPU topology; llm-d/GWIE/KAITO/KServe 会继续补语义。
  4. 硬件异构会倒逼 portable kernels。NVIDIA、AMD、TPU、XPU、CPU/edge 同时存在,Mojo/Triton/CuTeDSL/FlashInfer/MLX/ZML/llama.cpp 等抽象会继续抢“可移植性能层”。
  5. agent runtime 会像应用服务器一样标准化。durable execution、sandbox、short-lived credentials、human approval、evals/trace、MCP tool server 生命周期和状态恢复将成为生产 agent 的默认要求。
  6. 自研推理芯片会继续扩散。模型公司会把模型路线图、kernel、serving SLO 与芯片/网络/内存协同设计,但软件栈必须保留多硬件退路。
  7. 成本治理会前置到开发阶段。模型路由、budget、quota、prompt/cache policy、fallback 和审计不再是平台团队后补,而是应用架构的一部分。
