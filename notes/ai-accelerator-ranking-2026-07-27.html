一、结论先行:总排名

打分方法完全透明:每个维度取「该卡指标 ÷ H20 同指标」的比值 r,记 s = 1 + log2(r)(上限 8,下限 0),再按权重加权求和,归一化到 H20 = 100。 用 log2 而不是线性比值,是因为硬件指标跨了两个数量级(FP4 峰值最大差 136 倍),线性加权会让单一维度吃掉整张表。每翻一倍加 1 分,这个尺度更接近工程直觉。 权重:显存带宽 15、FP8 级算力 15、显存容量 10、FP4 级算力 10、能效 10、软件栈+MFU 10、数值格式 8、Scale-up 带宽 8、超节点域 7、片上 SRAM 7。

三条口径约定,决定了这张榜怎么读:(1) 某个维度没有公开数据时按基线取值(r = 1,既不加分也不减分),所以披露越少的厂商越靠近 100,不代表它弱; (2) 没有原生 FP4 的卡,「FP4 级算力」一列取它自己的最低精度稠密峰值,避免除零; (3) 软件栈维度以 CUDA = 1.0 封顶,按成熟度星级折算(★★★★★ = 1.00、★★★★ = 0.85、★★★ = 0.70、★★☆ = 0.62、★★ = 0.55),它只会扣别人的分,不会给别人加分。

雷达图比条形图更能说明「同分不同命」。MI455X 与 R200 几乎完全重合 —— 两张卡是同一种设计哲学的两个实现,差别只在小数点后。 Maia 200 的形状则完全不同:算力、带宽、容量三项都比它们矮一截,却在「超节点域」这根轴上直接顶满(6144 卡),外加 272 MB SRAM 和 750 W 的低功耗。 这就是超大规模厂商自研芯片的典型形状:不追单卡峰值,追「一个域里能装下多少张卡、每瓦出多少 token」。而 H20 那个几乎缩成一点的六边形提醒我们,基线本身有多低。
三条值得单独说的结论。 (1) MI455X 与 R200 的差距比标题党想象的小得多。纸面上 MI455X 的 FP8 20 PF 比 R200 的 17.5 PF 高 14%、MXFP4 40.26 PF 比 33.3 PF 高 21%,但综合指数只领先 4.8%(417 vs 398)—— 因为 R200 用第三代 Transformer Engine 的两级 micro-block NVFP4 缩放在「数值格式」上扳回,又用 CUDA 在软件维度拿满。折算实测 MFU 后有效 FP8 是 6.6 PF vs 6.13 PF,差 8%(见第九节)。 (2) 超大规模厂商的自研芯片第一次挤进前五。Maia 200 排第 4、TPU 8i 第 3,靠的都不是单卡峰值,而是超节点域 + 片上 SRAM + 能效这三项在本模型里合计占 24 分。它们不外售,但它们定义了 2026 年「一张卡该长什么样」的另一种答案。 (3) 披露少 ≠ 排名低,而是排名不可信。本模型对未公开维度按基线取值,所以壁仞 BR20X、昆仑芯 M100/M300、天数智芯天垓300 这些没有公开规格的卡根本进不了榜 —— 不是打分低,是没得打。看第二节的完整清单,不要只看榜。

三、显存、算力与算力/带宽比

这张表是整篇的地基。算力/带宽比(FLOP per Byte,也叫 roofline 的山脊点)决定了一张卡「天生偏算力还是偏带宽」: 算术强度低于山脊点的算子(decode 阶段的 GEMV、MoE 的稀疏 all-to-all、长上下文 attention 的 KV 读取)会撞带宽墙,算力再高也用不上。 H20 的山脊点只有 74 FLOP/B —— 合规阉割算力却保留了 4 TB/s HBM3,反而成了一张「decode 友好」的畸形好卡,这也是它至今还是很多中国推理集群基线的原因。

四、数值格式的原生支持

「支持 FP8」这句话在 2026 年已经不够用了。真正影响工程的是三件事:(1) Tensor Core / MME 是否原生做这个格式的矩阵乘(而不是软件模拟或先反量化再算); (2) 缩放是 per-tensor 还是 micro-block(MX / NVFP4 / HiF8) —— 微缩放决定 FP4 能不能真的用在训练而不掉精度;(3) 有没有配套的量化算子库。 昇腾 950 系列一口气加了 FP8 / MXFP8 / MXFP4 / HiF8 / HiF4,是这代国产卡最实质的一步;而 910C 完全没有 FP8,只能靠 BF16 硬扛,这是它在本次排名里被 950DT 拉开的核心原因。

六、片上 SRAM / L2:FlashAttention 到底能开多大

这一项经常被表格忽略,但它直接决定 kernel 怎么写。要分两层看:

  1. 每个计算核可编程的近存(shared memory / LDS / VMEM / SBUF) —— 它才是 FlashAttention 分块大小的硬上限。GPU 上 Hopper/Blackwell 每 SM 最多 228 KB shared memory,一个 BF16 的 128×128 tile 是 32 KB,所以 Q/K/V + 累加器要在 228 KB 里挤;Blackwell 又额外给了 256 KB TMEM 专供 Tensor Core。AMD CDNA4 每 CU 160 KB LDS。
  2. 全局末级缓存(L2 / Infinity Cache) —— 它决定 KV cache、权重分块、all-reduce 中间量有多少能不回 HBM。B200/B300 是 126 MB L2,MI355X 是 256 MB Infinity Cache,MI455X 是 2×96 MB L2。

而 TPU / Trainium 走的是完全不同的路线:用大块可编程 scratchpad 替代缓存。TPU 8i 有 384 MB 片上 SRAM(比 Ironwood 的 128 MB 多 3 倍),Google 的说法是「把模型的活跃工作集整个留在片上」;Trainium3 的 SBUF 是 256 MiB,并且是编译器显式管理的。 这解释了为什么这两家在长上下文 decode 上能拿到相对高的效率 —— 它们不是靠更大的 HBM 带宽,而是靠让 attention 的中间量根本不落 HBM。 微软走的是同一条路而且更激进:Maia 200 有 272 MB 片上 SRAM、80 TB/s,是 HBM 带宽(7 TB/s)的 11 倍,官方明确把它定位成「三层存储」的第一层,并提供 HBM→CSRAM 广播这样的显式数据编排原语。

七、非 HBM 路线:SRAM 派、LPDDR 派与晶圆级

前六节隐含了一个前提:加速卡 = 计算 die + 一圈 HBM。2026 年这个前提第一次被三家公司同时挑战,而且挑战的方向正好相反 —— 一派把内存做得极小极快(SRAM),一派把内存做得极大极慢(LPDDR)。它们没法用第一节那把尺子公平打分(Cerebras 的「一张卡」是一整片晶圆,Groq 的「一张卡」只有 500 MB),所以单独放在这里。

SRAM 派 —— 极小极快

Cerebras WSE-3:44 GB @ 21 PB/s(整片晶圆);NVIDIA Groq 3 LPU:0.5 GB @ 150 TB/s(单芯,机架 128 GB @ 40 PB/s);Tenstorrent Blackhole:194 MB/芯 @ 2.9 PB/s(整机)。 带宽比 HBM4 高 1–3 个数量级,代价是容量小 2–3 个数量级 —— 模型必须按层切开摊在几百颗芯片上,靠流水并行而不是张量并行来跑。

HBM 派 —— 平衡点(本文前六节的主角)

MI455X 432 GB @ 23.3 TB/s、R200 288 GB @ 22 TB/s、Maia 200 216 GB @ 7 TB/s。 容量与带宽都在「够用」的量级,所以能一张卡通吃 prefill 与 decode。代价是 HBM 本身的成本与功耗 —— 一张 R200 的 8 颗 HBM4 堆栈,占了整卡 BOM 与 1.8 kW 功耗里相当大的比例。

LPDDR / GDDR 派 —— 极大极慢

Qualcomm AI200:768 GB LPDDR5X/卡,整机架 160 kW 液冷;Intel Crescent Island:160 GB 起、伙伴可做到 480 GB,350 W 风冷 PCIe;Rubin CPX:128 GB GDDR7 @ 2 TB/s。 容量大到可以把多个模型 + 超长 KV cache 全部常驻,但带宽只有 HBM 卡的 1/5 到 1/15,只能吃大容量、低并发、算术强度高的负载。高通的 AI250 试图用 3D 堆叠 LPDDR 的近存计算(HBC)把「有效带宽」拉到 133 TB/s —— 注意这个「有效」是营销口径,The Register 已指出按 LPDDR5X 的位宽根本推不出这个数。

为什么这三条路能同时存在?因为 decode 和 prefill 对存储的要求本来就是相反的。 decode 是访存密集(算术强度 1–2 FLOP/B),要的是带宽和低延迟,SRAM 派赢;prefill 是算力密集(算术强度上千),要的是便宜的大容量,LPDDR/GDDR 派赢;而只有一种卡的机房,只能选平衡的 HBM 派。 2026 年的真实趋势是同一条推理链路上同时出现两三种硬件:NVIDIA 自己就在卖「Rubin NVL72(HBM)+ LPX 256(SRAM)+ CPX(GDDR)」三件套。 选型时该问的不再是「哪张卡最强」,而是「我的 prefill:decode 比例是多少,值不值得为它拆成两种硬件」。

八、TDP 与是否强制液冷

十一、选型结论

  1. 前沿训练(万亿参数 MoE):R200 与 MI455X 是唯一两个选项,决策点不是 PFLOPS 而是「你有没有 250 kW 机架 + 45 °C 冷液」和「你的栈是 CUDA 还是 ROCm」。若模型是超大 MoE,把预算优先给 scale-up 域(NVL144 / Helios 72 / UALoE),而不是给单卡峰值。
  2. 长上下文推理:走 PD 分离。prefill 用高山脊点、便宜显存的卡(Rubin CPX 是原生答案,昇腾 950PR 是同思路的国产版),decode 用高带宽 + 大 SRAM 的卡(R200 / TPU 8i / 950DT)。用一种卡同时干两件事在 2026 年已经是浪费。
  3. 国产替代:昇腾 950DT 是这一代唯一在数值格式(FP8/MXFP4/HiF8)、带宽(4 TB/s)、超节点(8192 卡)三项上同时够格的国产卡;思元690 靠 196 GB 显存打大模型单卡部署;海光深算四号的卖点是类 CUDA 迁移成本 <5%(算子兼容 >99%,DTK/DAS 支持 vLLM/SGLang),适合存量 CUDA 代码多、不想重写 kernel 的团队;S5000 / C600 / L600 的优势同样是 vLLM/SGLang/Megatron 迁移几乎零成本;壁仞 BR20X(2026 Q4)与天数智芯天垓300 值得盯,但在它们公布显存/带宽/TFLOPS 之前无法评估。选型时务必要求实测 MFU 与端到端 tokens/s,而不是峰值 TFLOPS。
  4. 存量风冷机房:Crescent Island(350 W、160–480 GB LPDDR5X)、Gaudi 3(900 W 风冷)和 Tenstorrent Galaxy(整机 8–10 kW 风冷、11 万美元起)是少数还能塞进老机房的选择,代价是带宽只有 HBM 卡的 1/5 到 1/15,只适合大显存、低并发的 agent 推理。
  5. 极低延迟 decode(agent / 代码补全):这是 2026 年新出现的一档需求。要的不是吞吐而是单用户 tok/s,山脊点越低越好 —— NVIDIA Groq LPX(8 FLOP/B)、Cerebras CS-3(6)、Tenstorrent Galaxy 是仅有的三个答案,而它们都要求你把模型按层摊到几百颗芯片上,和「一台 8 卡机跑一个模型」是完全不同的部署心智。
  6. 不外售的卡也要看:Maia 200、TPU 8i/8t、Trainium3、MTIA 500 你买不到,但你会通过 Azure / GCP / AWS / Meta 的 API 间接为它们付费。它们的规格决定了云上 token 的成本下限 —— 比如 Maia 200 排到第 4,意味着 Azure 有底气在 GPT-5.2 这类负载上打价格战。
  7. 方法论警告:本文任何一个排名都不该单独用于采购。峰值算力的可信度 > 带宽 > SRAM > MFU;而对 TCO 的影响顺序恰好相反 —— MFU 和液冷改造费才是真正花钱的地方。另外注意「有效带宽」这类词:高通 AI250 的 133 TB/s 与 AI200 机架的 414 TB/s 都是厂商自定义口径,不能和 HBM 的物理带宽直接比。
