这是一份滚动更新的商用 AI 加速卡统计,本次快照 2026-07-29。覆盖 27 家厂商、每家最新 3 款卡:NVIDIA、AMD、华为昇腾、Google TPU、AWS Trainium、Intel、Microsoft、Meta、阿里平头哥、Tesla、SambaNova、d-Matrix、Etched、FuriosaAI、Rebellions、Qualcomm、Cerebras、Tenstorrent、百度昆仑芯、寒武纪、摩尔线程、沐曦、海光、壁仞、燧原、天数智芯、东方算芯。 排名不看单一峰值,而是把显存、算力、算力/带宽比、数值格式原生支持、Scale-up 与超节点域、片上 SRAM/L2、TDP 与液冷、软件栈成熟度与实测 MFU 十个维度加权成一个「综合硬件指数」,并统一以 NVIDIA H20 = 100 为基线。 所有关键数字都在表格里给出来源链接;公开信息不足、由我按同代规格推算的单元格标注 ※,请不要当成厂商官方口径。

零、2026-07-29 复核:一层网络 256 卡,超节点从独门武艺变成标准动作

上一版(07-28)的结论是「域装不装得下」取代了「单卡峰值」成为 3T 级模型的第一判据,并据此把 MI355X、Gaudi 3、思元690、沐曦 / 燧原 / 摩尔线程、RNGD、B30A 一起划进了「域太小、过不了 64 卡线」那一栏。 这个判断在数据层面有一处错:我当时对三家国产 GPU 的 scale-up 域取的是「一层 8 卡」,而 WAIC 2026(07-17 至 07-20)上这三家已经各自公布了整柜级方案。补齐之后结论要改写:

  • 摩尔线程 MTT C256:柜内 Cable Tray 全铜架构,一层 Scale-up 网络直连 256 颗 GPU —— 标准单宽机柜 128 卡全互联,并柜到 256 卡,卡间延迟压到亚微秒级。这是目前公开方案里一层网络卡数最多的一个(行业常见是一层 64 卡)。
  • 沐曦 曦景 S600:OEX 正交连接器 + 两级交换拓扑,单机柜 64 卡全互联,柜间可扩到万卡规模。
  • 燧原 云燧 ESL64-O(与中兴通讯联合发布):OEX 正交无背板、零线缆,单柜 64 卡,可并柜到 128 / 256 / 512 卡,官方口径 2026 年底量产。

也就是说,「用域规模补单卡工艺差」这件事在 2026 上半年还是华为一家的叙事,到这个夏天已经是整个国产阵营的集体共识:壁仞 1024 卡光互联、昆仑芯天池 256 / 512、阿里 ICN Switch 64 卡、 摩尔线程 256、沐曦 / 燧原 / 东方算芯各自 64 —— 连互联介质都分化出了三条路(全铜 Cable Tray、OEX 正交零线缆、NPO 光互联)。 华为这边则在 07-29 首次公开展示昇腾 950 超节点整机与国内首发的 800GE AI 网卡(支持 10 万级节点组网),把同一件事推到了 scale-out 层。

另外两条本次要记的账:(1) AMD 与 Cerebras 在 Advancing AI 2026(07-23)宣布把 PD 分离拆到两家公司 —— Helios 机架做 prefill、晶圆级引擎做 decode,官方口径相对纯 WSE 方案每瓦 token 提升最多 5 倍; (2) Kimi K3 开源后 48 小时内,昇腾、阿里真武 M890、海光 DCU、摩尔线程 S5000 以及一批海外托管厂商全部宣布 Day-0 适配,而它们给出的证据等级差别很大 —— 这是本文「第三层」第一次能用同一个负载横向比。

形态五:跨厂商异构(云侧拼装)
NVIDIA H200SambaNova SN50 · RDU

SambaNova 在 RAISE Summit 2026 演示的方案:用别人的 GPU 做 prefill、自己的 RDU 做 decode。这一档的意义在于它不需要任何厂商合作 —— 只要两边都接了 vLLM,PD 分离就是一个部署选择。

把五种形态并排放,能看到 2026 年硬件分工的演化路径:从「一张卡的两个阶段」→「一家公司的两颗芯片」→「两家公司的两种架构」。 AMD × Cerebras 这一步的分量不在于性能数字,而在于它承认了没有一家能同时拿下 prefill 和 decode —— AMD 有 HBM4 和 UALink 机架,但在单用户 decode 延迟上打不过晶圆级 SRAM; Cerebras 有 21 PB/s 的片上带宽,但 44 GB 容量吃不下前沿模型的 prefill(第零之二节算过:装一份 K3 要 64–91 片晶圆)。互补的短板刚好拼成一条完整链路。 对采购的直接含义:「买哪张卡」这个问题正在被「买哪一段」取代。如果你的负载是 agent(短 prompt、长输出、单用户延迟敏感),decode 段的钱比 prefill 段值; 如果是文档理解或代码库级 RAG(超长 prompt、短输出),反过来。而形态五说明这件事已经不需要等厂商合作 —— 只要 prefill 和 decode 两侧都接了 vLLM,你自己就能拼。 这也是为什么第九节那张 MFU 表里「有没有接 vLLM」比「峰值多少」更值得看。

一、结论先行:总排名

打分方法完全透明:每个维度取「该卡指标 ÷ H20 同指标」的比值 r,记 s = 1 + log2(r)(上限 8,下限 0),再按权重加权求和,归一化到 H20 = 100。 用 log2 而不是线性比值,是因为硬件指标跨了两个数量级(FP4 峰值最大差 136 倍),线性加权会让单一维度吃掉整张表。每翻一倍加 1 分,这个尺度更接近工程直觉。 权重:显存带宽 15、FP8 级算力 15、显存容量 10、FP4 级算力 10、能效 10、软件栈+MFU 10、数值格式 8、Scale-up 带宽 8、超节点域 7、片上 SRAM 7。

三条口径约定,决定了这张榜怎么读:(1) 某个维度没有公开数据时按基线取值(r = 1,既不加分也不减分),所以披露越少的厂商越靠近 100,不代表它弱; (2) 没有原生 FP4 的卡,「FP4 级算力」一列取它自己的最低精度稠密峰值,避免除零; (3) 软件栈维度以 CUDA = 1.0 封顶,按成熟度星级折算(★★★★★ = 1.00、★★★★ = 0.85、★★★ = 0.70、★★☆ = 0.62、★★ = 0.55),它只会扣别人的分,不会给别人加分。

三条值得单独说的结论。 (1) MI455X 与 R200 的差距比标题党想象的小得多。纸面上 MI455X 的 FP8 20 PF 比 R200 的 17.5 PF 高 14%、MXFP4 40.26 PF 比 33.3 PF 高 21%,但综合指数只领先 4.8%(417 vs 398)—— 因为 R200 用第三代 Transformer Engine 的两级 micro-block NVFP4 缩放在「数值格式」上扳回,又用 CUDA 在软件维度拿满。折算实测 MFU 后有效 FP8 是 6.6 PF vs 6.13 PF,差 8%(见第九节)。 (2) 超大规模厂商的自研芯片第一次挤进前五。Maia 200 排第 4、TPU 8i 第 3,靠的都不是单卡峰值,而是超节点域 + 片上 SRAM + 能效这三项在本模型里合计占 24 分。它们不外售,但它们定义了 2026 年「一张卡该长什么样」的另一种答案。 (3) 披露少 ≠ 排名低,而是排名不可信。本模型对未公开维度按基线取值,所以壁仞 BR20X、昆仑芯 M100/M300、天数智芯天垓300、Etched Sohu、Tesla AI5、d-Matrix Raptor、Intel Crescent Island 这些没有完整公开规格的卡根本进不了榜 —— 不是打分低,是没得打。看第二节的完整清单,不要只看榜。 反过来也要警惕:阿里真武 M890 有四个维度按基线取值,它的 164 分里有相当一部分是「未公开」的默认值,不要当成实测结论。 (4) 这张榜会因为新披露而改分,而且第一次改分就动了 3 张卡(2026-07-29)。规则写在这里:只有当某一维出现可引用的新公开数据时才重算,重算只动那一维、其余输入逐字沿用,并在第零节留下改动前后的对照。 所以引用本文的分数请一并引用快照日期 —— 一个会更新的榜比一个不更新的榜有用,但前提是每次更新都说清楚改了哪一维。

为什么按路线分:同一阵营的卡在第一节的雷达形状高度相似,跨阵营则完全不同。 HBM 派拼的是每一代 HBM 的容量与速率;自研 ASIC 派拼的是域规模与自家负载闭环;超节点派用互联规模换单卡工艺差;新势力赌的是「HBM 不是唯一解」;迁移成本派卖的其实不是硬件峰值,而是「你的 PyTorch/vLLM 代码不用改」。 2026-07-28 新增的第六个阵营是本次复核里最值得说的结构变化:「推理专用 ASIC / 自用派」把通用性当成可以牺牲的东西。 Etched 直接把 transformer attention 烧成固定功能电路,代价是完全不兼容 CUDA / vLLM / TensorRT-LLM,必须用它自己的编译器重建整条推理栈; FuriosaAI 用 180 W 无源散热换「插进任何风冷机房」;Rebellions 用 UCIe-Advanced 把四颗 chiplet 拼成一颗; 阿里平头哥和 Tesla 则干脆不外售 —— 前者只服务阿里云与千问,后者只服务 Optimus 与 FSD。 这个阵营和「超大规模自研 ASIC」的区别在于:后者是巨头为自家云做的,前者里有一半是创业公司押注「某一种负载会长期存在」,赌错了就没有第二条产品线。 2026-07-29 有两处需要动这张版图。(1) 第四格从「存内」扩成「存内 / 近存」,因为新入榜的东方算芯走的是第三种做法: Cerebras / Groq 把权重搬进 SRAM、d-Matrix 让乘法发生在 SRAM 单元里,而东方算芯是把 DRAM 晶圆直接键合到逻辑晶圆上 —— 存储仍然不参与计算,只是把距离压到亚微米。三条路的共同点是都不买 HBM。 (2) 第三格「超节点补偿派」实际上已经不成一格了:摩尔线程(256 卡)、沐曦(64)、燧原(64)、东方算芯(64)在这个夏天全部补上了整柜互联,而它们本来被归在「迁移成本派」。 换句话说,「用域规模补单卡」从一种路线选择变成了国产阵营的公共前提 —— 到 2027 年这一格大概会消失,因为没有哪家还会不做超节点。

四、数值格式的原生支持

「支持 FP8」这句话在 2026 年已经不够用了。真正影响工程的是三件事:(1) Tensor Core / MME 是否原生做这个格式的矩阵乘(而不是软件模拟或先反量化再算); (2) 缩放是 per-tensor 还是 micro-block(MX / NVFP4 / HiF8) —— 微缩放决定 FP4 能不能真的用在训练而不掉精度;(3) 有没有配套的量化算子库。 昇腾 950 系列一口气加了 FP8 / MXFP8 / MXFP4 / HiF8 / HiF4,是这代国产卡最实质的一步;而 910C 完全没有 FP8,只能靠 BF16 硬扛,这是它在本次排名里被 950DT 拉开的核心原因。

五、Scale-up 互联与超节点域规模

单卡指标已经不是 2026 年的主战场。真正决定能不能训万亿参数、能不能把 MoE 的 expert 全放进一个内存域的,是一个 scale-up 域里能塞多少张卡、卡间带宽多少。 这里出现了本次统计最戏剧的一组数字:华为昇腾用 8192 卡的 Atlas 950 SuperPoD 换取单卡劣势,Google 用 3D Torus + OCS 做到 9216 卡,微软用纯以太网做到 6144 卡,而 NVIDIA/AMD 的机架域仍是 72 卡量级。

六、片上 SRAM / L2:FlashAttention 到底能开多大

这一项经常被表格忽略,但它直接决定 kernel 怎么写。要分两层看:

  1. 每个计算核可编程的近存(shared memory / LDS / VMEM / SBUF) —— 它才是 FlashAttention 分块大小的硬上限。GPU 上 Hopper/Blackwell 每 SM 最多 228 KB shared memory,一个 BF16 的 128×128 tile 是 32 KB,所以 Q/K/V + 累加器要在 228 KB 里挤;Blackwell 又额外给了 256 KB TMEM 专供 Tensor Core。AMD CDNA4 每 CU 160 KB LDS。
  2. 全局末级缓存(L2 / Infinity Cache) —— 它决定 KV cache、权重分块、all-reduce 中间量有多少能不回 HBM。B200/B300 是 126 MB L2,MI355X 是 256 MB Infinity Cache,MI455X 是 2×96 MB L2。

而 TPU / Trainium 走的是完全不同的路线:用大块可编程 scratchpad 替代缓存。TPU 8i 有 384 MB 片上 SRAM(比 Ironwood 的 128 MB 多 3 倍),Google 的说法是「把模型的活跃工作集整个留在片上」;Trainium3 的 SBUF 是 256 MiB,并且是编译器显式管理的。 这解释了为什么这两家在长上下文 decode 上能拿到相对高的效率 —— 它们不是靠更大的 HBM 带宽,而是靠让 attention 的中间量根本不落 HBM。 微软走的是同一条路而且更激进:Maia 200 有 272 MB 片上 SRAM、80 TB/s,是 HBM 带宽(7 TB/s)的 11 倍,官方明确把它定位成「三层存储」的第一层,并提供 HBM→CSRAM 广播这样的显式数据编排原语。

一句话结论:GPU 阵营靠「大 L2 + 小而快的 smem」,TPU/Trainium 靠「超大可编程 scratchpad」。 前者写 kernel 更灵活(FlashAttention 各种变体都能落),后者更依赖编译器,但在固定形状的长上下文 attention 上更容易接近峰值。昇腾 950 这代没有公开 SRAM 数字,但把内存访问粒度从 512 B 降到 128 B —— 对 MoE / 稀疏 attention 这类碎片化访存,这个改动的收益比堆 SRAM 更直接。 注意 d-Matrix 与 SN50 两张卡的条形是被刻度截断的(本图满刻度是 TPU 8i 的 384 MB)。加进来之后能看到第三种设计哲学: SRAM 不再只是「缓存」或「scratchpad」,而是被当成一层可寻址的内存来卖。 SN50 的 432 MB 是「三层内存」的第一层,模型可以在 SRAM ↔ HBM 之间毫秒级热切换 —— 这正是 agent 负载的关键动作(频繁在多个模型间跳); d-Matrix 的 4 GB 更极端,乘法就发生在改造过的 SRAM 单元里(数字存内计算),所以它的「SRAM 容量」实际上等于「能同时驻留多少权重」。 而 FuriosaAI RNGD 是 SRAM/HBM 比最高的一张卡:256 MB 片上 SRAM 对 48 GB HBM,比例约 1:190(H20 是 1:1600),外加只有 180 W —— 这是「用片上容量换 HBM 带宽和功耗」这条路线做得最干净的一个样本。

七、非 HBM 路线:SRAM 派、LPDDR 派与晶圆级

前六节隐含了一个前提:加速卡 = 计算 die + 一圈 HBM。2026 年这个前提第一次被三家公司同时挑战,而且挑战的方向正好相反 —— 一派把内存做得极小极快(SRAM),一派把内存做得极大极慢(LPDDR)。它们没法用第一节那把尺子公平打分(Cerebras 的「一张卡」是一整片晶圆,Groq 的「一张卡」只有 500 MB),所以单独放在这里。

SRAM 派 —— 极小极快

3D 近存 DRAM 派 —— 把内存搬到计算正上方(07-29 新增)

东方算芯 巅峯 DF1000:6.4 TB/s,没有一颗 HBM。做法是用 Hybrid Bonding 把 DRAM 晶圆与逻辑晶圆无凸点垂直键合,互连间距从传统硅中介层 + 微凸点的数十微米压到亚微米级,TSV 数量多出几十倍,官方口径是同容量下带宽为 HBM 的 5 倍以上,并可通过增加堆叠层数继续扩容。 它和 SRAM 派的区别在于存储仍然不参与计算(不是存内计算),只是把搬运距离压到极短;和 HBM 派的区别在于它不需要 CoWoS 与 HBM 供应,14nm 成熟工艺 + 全国产供应链就能流片。 代价是算力被工艺锁住(BF16 520 TFLOPS)、容量与 TDP 至今未公开,以及一套全新的 CAAP 软件栈。高通的 AI250(HBC:把 LPDDR 3D 堆到计算上面)与 d-Matrix 的 Raptor(3DIMC)本质上在做同一件事,只是介质不同。

HBM 派 —— 平衡点(本文前六节的主角)

MI455X 432 GB @ 23.3 TB/s、R200 288 GB @ 22 TB/s、Maia 200 216 GB @ 7 TB/s。 容量与带宽都在「够用」的量级,所以能一张卡通吃 prefill 与 decode。代价是 HBM 本身的成本与功耗 —— 一张 R200 的 8 颗 HBM4 堆栈,占了整卡 BOM 与 1.8 kW 功耗里相当大的比例。

LPDDR / GDDR 派 —— 极大极慢

Qualcomm AI200:768 GB LPDDR5X/卡,整机架 160 kW 液冷;Intel Crescent Island:160 GB 起、伙伴可做到 480 GB,350 W 风冷 PCIe;Rubin CPX:128 GB GDDR7 @ 2 TB/s; Tesla AI5:144–192 GB LPDDR5X、384-bit 位宽(12 颗 SK hynix 模块),这是同一条路线在车端/机器人端的实现 —— 整颗 die 全是 8-bit MAC 阵列,连 ISP 都省掉。 容量大到可以把多个模型 + 超长 KV cache 全部常驻,但带宽只有 HBM 卡的 1/5 到 1/15,只能吃大容量、低并发、算术强度高的负载。高通的 AI250 试图用 3D 堆叠 LPDDR 的近存计算(HBC)把「有效带宽」拉到 133 TB/s —— 注意这个「有效」是营销口径,The Register 已指出按 LPDDR5X 的位宽根本推不出这个数。

为什么这三条路能同时存在?因为 decode 和 prefill 对存储的要求本来就是相反的。 decode 是访存密集(算术强度 1–2 FLOP/B),要的是带宽和低延迟,SRAM 派赢;prefill 是算力密集(算术强度上千),要的是便宜的大容量,LPDDR/GDDR 派赢;而只有一种卡的机房,只能选平衡的 HBM 派。 2026 年的真实趋势是同一条推理链路上同时出现两三种硬件:NVIDIA 自己就在卖「Rubin NVL72(HBM)+ LPX 256(SRAM)+ CPX(GDDR)」三件套。 选型时该问的不再是「哪张卡最强」,而是「我的 prefill:decode 比例是多少,值不值得为它拆成两种硬件」。 07-29 有一件事让这一节的地位变了:晶圆级不再只是「进不了榜的异类」,它进了别人的产线。 AMD 与 Cerebras 在 07-23 宣布把 Helios 机架(72×MI455X、2.9 EF FP4、31 TB HBM4、UALoE 260 TB/s)和晶圆级引擎串成一条推理流水线: HBM 派做 prefill、SRAM 派做 decode,官方称每瓦 token 相对纯晶圆级方案最多 ×5,支持 1T+ 参数模型,2026 H2 先上 Cerebras Cloud,而 Cerebras 会把 AMD 机架部署进自己的数据中心。 这条新闻验证了本节开头那个判断的下半句:三条存储路线不是三种「谁会赢」的赌注,而是一条链路上的三段分工。 照这个逻辑,3D 近存这一派最可能的位置也不是取代 HBM,而是吃掉「带宽要够、容量不必大、成本要低」的那一段 —— 恰好是 decode 和中等规模模型常驻。

十一、选型结论

  1. 前沿训练(万亿参数 MoE):R200 与 MI455X 是唯一两个选项,决策点不是 PFLOPS 而是「你有没有 250 kW 机架 + 45 °C 冷液」和「你的栈是 CUDA 还是 ROCm」。若模型是超大 MoE,把预算优先给 scale-up 域(NVL144 / Helios 72 / UALoE),而不是给单卡峰值。
  2. 长上下文推理:走 PD 分离。prefill 用高山脊点、便宜显存的卡(Rubin CPX 是原生答案,昇腾 950PR 是同思路的国产版),decode 用高带宽 + 大 SRAM 的卡(R200 / TPU 8i / 950DT)。用一种卡同时干两件事在 2026 年已经是浪费。
  3. 国产替代:昇腾 950DT 是这一代唯一在数值格式(FP8/MXFP4/HiF8)、带宽(4 TB/s)、超节点(8192 卡)三项上同时够格的国产卡;思元690 靠 196 GB 显存打大模型单卡部署;海光深算四号的卖点是类 CUDA 迁移成本 <5%(算子兼容 >99%,DTK/DAS 支持 vLLM/SGLang),适合存量 CUDA 代码多、不想重写 kernel 的团队;S5000 / C600 / L600 的优势同样是 vLLM/SGLang/Megatron 迁移几乎零成本,而且2026-07-29 起它们都有了整柜方案(MTT C256 一层 256 卡、曦景 S600 单柜 64、云燧 ESL64-O 单柜 64 但要等年底量产)—— 如果你的模型是大 MoE,这三张卡的可选性和半年前完全不同;壁仞 BR20X(2026 Q4)与天数智芯天垓300 值得盯,但在它们公布显存/带宽/TFLOPS 之前无法评估。选型时务必要求实测 MFU 与端到端 tokens/s,而不是峰值 TFLOPS。
  4. 存量风冷机房(2026-07-29 改写):这一档原本只有 Crescent Island(350 W、160–480 GB LPDDR5X)、Gaudi 3(900 W 风冷)、Tenstorrent Galaxy(整机 8–10 kW 风冷、11 万美元起)和 FuriosaAI RNGD(180 W 被动散热), 共同代价是带宽只有 HBM 卡的 1/5 到 1/15,只适合大显存、低并发的 agent 推理。华为 Atlas 850E 风冷超节点改变了这个取舍:靠 VCE 相变散热做到不改液冷基建、标准机柜直接上架, 同时保住 4.0 TB/s 内存带宽(与 H20 同档)、96 卡单域、mxFP4 全格式覆盖、10 ms 级时延。如果你的约束是「机房不能改」而负载又是大 MoE 推理,这是目前唯一不用在带宽上大幅让步的选项 —— 但要求供应商提供长期满载下的相变散热衰减数据与整柜功率密度,这两项官方都还没公开 ※。
  5. 极低延迟 decode(agent / 代码补全):这是 2026 年新出现的一档需求。要的不是吞吐而是单用户 tok/s,山脊点越低越好 —— NVIDIA Groq LPX(8 FLOP/B)、Cerebras CS-3(6)、Tenstorrent Galaxy 是仅有的三个答案,而它们都要求你把模型按层摊到几百颗芯片上,和「一台 8 卡机跑一个模型」是完全不同的部署心智。
  6. 不外售的卡也要看:Maia 200、TPU 8i/8t、Trainium3、MTIA 500 你买不到,但你会通过 Azure / GCP / AWS / Meta 的 API 间接为它们付费。它们的规格决定了云上 token 的成本下限 —— 比如 Maia 200 排到第 4,意味着 Azure 有底气在 GPT-5.2 这类负载上打价格战。
  7. 部署 3T 级开源模型(2026-07-28 新增):先算「几张卡 + 够不够一个域」,再看峰值。以 Kimi K3 为例,MXFP4 权重 1.4 TB、官方要求 ≥64 卡超节点,于是决策顺序变成:(a) 卡有没有原生 MXFP4(没有就 ×2 或 ×4 显存足迹,910C 这类卡直接从 14 张变 63 张);(b) 域装不装得下(72 卡机架和 8192 卡超节点在这道题上没差别,但 8 卡 UBB 就必须跨域,而跨域正是官方让你避免的);(c) 才是 PFLOPS。按这个顺序,昇腾 950 系列 / TPU / Maia / Trainium3 / 真武 M890 / 昆仑芯天池 这些「域优先」的产品比它们的单卡指数看起来更强。
  8. 推理专用 ASIC 值不值得(2026-07-28 新增):Etched Sohu、d-Matrix Corsair、SambaNova SN50、FuriosaAI RNGD 这一档的共同卖点是单位 token 成本,共同代价是生态。判断标准只有两条:一是你的模型架构会不会在硬件生命周期内变(Sohu 把 transformer 烧进了电路,押的就是「不会变」);二是你能不能承受没有 CUDA/vLLM —— Sohu 要求完全重写,RNGD / SN50 / Corsair 已接 vLLM 或提供分布式引擎,迁移成本差一个数量级。反过来,如果你的诉求只是「进得了现有风冷机房」,RNGD 的 180 W 被动散热和 d-Matrix 的免液冷机架是目前最直接的答案。
  9. 怎么读「超节点」这三个字(2026-07-29 新增):域内卡数只是第一个数字,还要追问另外四个 —— (a) 是几层网络(摩尔线程一层 256 卡 vs 行业常见一层 64 卡再往上叠,层数决定跨卡延迟的方差); (b) 介质是什么(柜内全铜 Cable Tray 带宽利用率高但线缆多,OEX 正交零线缆运维省事但一柜只能 64,NPO 光互联能到千卡但成本与故障域另算); (c) 是不是单一内存域(MI355X「风冷 64 卡 / 液冷 128 卡」是机架密度,不是一个 scale-up 域,这两件事经常被混着讲); (d) 什么时候能交付(云燧 ESL64-O 的口径是 2026 年底量产,昆仑芯天池 256 已上市,差别是一整个采购周期)。 一句话:「一层多少卡 + 什么时候能提货」比「域上限多少卡」更有决策价值。
  10. 把 PD 分离当成采购单位(2026-07-29 新增):AMD × Cerebras 之后,「prefill 用一家、decode 用另一家」已经是厂商自己在卖的方案,不再是极客拼装。 落地时按三步走:(a) 先量自己的 prefill:decode token 比例(agent 类负载通常 1:10 以上,文档理解类可能反过来); (b) 再看两侧是否都接了 vLLM —— 这是拼装可行性的唯一硬门槛,SN50 / RNGD / Corsair / 昇腾 / 海光都接了,Etched Sohu 没接; (c) 最后算跨段传输的代价:KV cache 要从 prefill 侧搬到 decode 侧,这条链路的带宽和延迟经常是整个方案的真实瓶颈,而它不在任何一张卡的 datasheet 上。
  11. 方法论警告:本文任何一个排名都不该单独用于采购。峰值算力的可信度 > 带宽 > SRAM > MFU;而对 TCO 的影响顺序恰好相反 —— MFU 和液冷改造费才是真正花钱的地方。另外注意「有效带宽」这类词:高通 AI250 的 133 TB/s 与 AI200 机架的 414 TB/s 都是厂商自定义口径,不能和 HBM 的物理带宽直接比。
