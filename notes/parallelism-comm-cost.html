并行策略的通信量账本The Communication Bill of Parallelism

选并行策略最后都会归到一个问题:这么切,每张卡每步要多传多少字节? 这篇把 DP / TP / PP / EP / CP 放进同一套符号里各算一遍,给出与 B、S、H、L 和并行度的比例关系, 再横向比,最后落到两个实际问题:怎么排布,以及最少要几张卡。

前置两篇:TP / PP / EP 怎么切到张量 shape 上讲的是切法, 主流序列并行方案对比讲的是 SP 各方案的机制与原语。 这篇不重复机制,只算账。

一、统一符号

后面所有公式都用这一套记号,N 一律表示该维度自己的并行度:

符号含义本文取值
B单卡 micro-batch1
S序列长度4096
Hhidden size4096
HkvKV 宽度 = kv_heads × head_dim1024
L层数80
P参数量295 B
kMoE top-k8
b字节/元素(bf16)2
A单层激活张量 = B·S·H·b32 MiB

取值参照 Hy3 的量级。单层激活 A = 32 MiB 这个数很有用 —— 后面几乎所有通信量都是它的若干倍。

四、DP:通信量只跟参数量有关

DP 每卡一份完整模型,算完各自的梯度后做一次 All-Reduce。关键特征是: 它的通信量与 S、B 完全无关,只跟参数量走,而且每个 step 才一次。

每卡每 step 朴素 DP = 2·(N−1)/N · Pg · b ≈ 2 Pg b
ZeRO-3 = 前向 AllGather + 反向 AllGather + 梯度 ReduceScatter ≈ 3 Pg b

Pg 是 DP 组内每份副本的参数量,即 P / (TP·PP·EP) —— 如果同时开了 TP / PP / EP,参数已经被它们切过,DP 只在剩下的那份上同步。

这里有个很容易搞错的点:分母里没有 DP 度。 ZeRO-3 把参数分片存放,但 All-Gather 要把它们拼回完整的一份才能算, 所以每卡收发量 ≈ 完整参数量,加 DP 卡并不会让每卡的通信量下降,只是把 batch 摊薄了。 ZeRO-3 比朴素 DP 多 1.5 倍通信,换来参数、梯度、优化器状态全部分片 —— 对 295B 这个量级这是唯一可行的选择,光 AdamW 的状态就是权重的 7 倍。

五、TP:每层两次全归约,与序列成正比

TP 把每个算子内部切开,代价是每层都要把结果拼回来:attention 的 o_proj 之后一次 All-Reduce, FFN 的 down_proj 之后一次。反向再来两次。

每卡每 micro-batch(整模型) TP = 4 次 × 2·(N−1)/N · A × L ≈ 8 · L · B·S·H·b
L=80, A=32 MiB, N=8 → 约 17.5 GiB

17.5 GiB。这是所有策略里最大的一档,而且注意分子里有 S —— 序列翻倍,通信量就翻倍。 更要命的是频率:每层 4 次,80 层就是 320 次集合通信,每一次都是同步点。 这就是TP 必须压在 NVLink 域内的原因,跨节点做 TP 基本等于自杀。

Megatron-SP 是免费搭档。它把 TP 的 All-Reduce 拆成 Reduce-Scatter + All-Gather —— 2X = X + X,总量一个字节都没变,但 LayerNorm / Dropout 那段激活也跟着被切成 N 份。 白拿的显存,没有不开的理由。

六、PP:通信最省,代价是气泡

PP 只在 stage 边界传激活,层内什么都不用传。这让它成为通信量最小的策略,小两个数量级。

每个 stage 边界、每个 micro-batch PP = 前向 A + 反向 A = 2 · B·S·H·b = 64 MiB
对比 TP 的 17.5 GiB,差约 280 倍

而且是 P2P —— 只跟相邻 stage 说话,不是集合通信,天然可以跨节点走 IB。 PP 的代价不在带宽,在气泡:

流水线气泡占比 bubble = (Npp − 1) / (M + Npp − 1)
M = micro-batch 数。M=8, N=4 → 27%;M=32, N=4 → 8.6%

所以 PP 的经验法则是 M ≥ 4·Npp。 调度上 GPipe → 1F1B → interleaved 1F1B → zero-bubble 这条演进线,做的都是同一件事:把这个分数榨小。

七、EP:All-to-All,被 top-k 放大

EP 把专家分到不同卡上,于是每个 token 要被送到选中专家所在的卡(dispatch), 算完再收回来(combine)。前向两次 All-to-All,反向两次。

每卡每 micro-batch(全部 MoE 层) EP = 4 次 × (N−1)/N · min(k, N) · A × Lmoe
k=8, N=8, L=80 → 约 70 GiB

min(k, N) 那一项是关键:一个 token 选了 k 个专家,但如果其中几个恰好落在同一张卡上, 只需要发一次。所以放大倍数是 k 和 Nep 里的较小者。 k=8 时这个放大非常凶 —— EP 的通信量能轻松超过 TP。

另一个坑是 All-to-All 怕长尾:它要等最慢的那一对完成。如果路由不均衡,某张卡收到的 token 远多于平均, 整个集合通信就被它拖住。这正是 EPLB(把热门专家复制到多卡)存在的理由。

八、CP:Ulysses 与 Ring 的分水岭

切序列有两条路线,它们的通信量随并行度的走势完全相反,这是选型的核心依据。

每卡每 micro-batch(整模型) Ulysses = 2 × (2H + 2Hkv) · B·S·b · (N−1)/N² · L ~ O(1/N)
Ring = 2 × 2 · B·S·Hkv·b · (N−1)/N · L ~ O(1)

Ulysses 的量随 N 递减,Ring 的量随 N 递增然后趋于常数。 原因在原语:Ulysses 用 All-to-All,每卡只发自己那份小分片,N 越大分片越小; Ring 要绕环 N−1 步,步数随 N 涨,抵消了每步块变小的好处。

动图 3:两条路线随并行度的走势(交叉点在 N≈4–8)
NUlysses(All-to-All)Ring(P2P 环)
N 小的时候 Ring 更省,N 大的时候 Ulysses 更省,交叉点在 4 到 8 之间。 但 Ulysses 有个硬上限:并行度不能超过 head 数(GQA 下受 KV head 数掐得更紧,比如 Hy3 只有 8)。 所以真正的选型是:head 够分就用 Ulysses,不够分就上 Ring,又长又要大并行就用 USP 把两者叠成 2D。

十、实战:先定排布,再定并行度

知道了量级,选型就有了依据。实战里最容易被忽略、也最致命的一步不是"选哪个策略",而是 把哪个策略放进 NVLink 域。同样的 TP=8,放节点内和跨节点能差一个数量级。

动图 5:按通信量排布 —— 谁进 NVLink,谁走 IB

TP · 17.5 GiB EP · 70 GiB(若装得下)
节点间 IB~50–400 GB/s
CP · 1–2 GiB DP · 每 step 一次
最外层可跨机架
PP · 64 MiB/边界,P2P
排序原则很简单:通信量大、频率高、且是集合通信的往里放。 TP 每层 4 次同步,必须最内;PP 只在边界 P2P 一次,放最外;DP 虽然量大但每 step 才一次,而且能和反向计算重叠,可以往外放。

PP 气泡大加 micro-batch而不是减 PP 度;M ≥ 4·Npp

十一、最少要几张卡

先算显存下界,再找一组能整除的并行度组合。训练和推理的公式完全不同, 因为训练要装优化器状态,推理要装 KV cache。

训练(混合精度 + AdamW + ZeRO-3) 每参数字节 = bf16 权重 2 + bf16 梯度 2 + fp32 master 4 + Adam m 4 + v 4 = 16 B/param
Nmin = ⌈ (16·P + 激活) / (C · u) ⌉
推理 Nmin = ⌈ (P·bw + 2·L·Hkv·b·S·并发) / (C · u) ⌉

C 是单卡显存,u 是可用率(框架 workspace、碎片、通信缓冲,一般取 0.85–0.9)。 算出下界之后还要满足整除约束,否则跑不起来:

合法性约束 总卡数 = TP × CP × PP × DP
TP | num_kv_heads(否则 KV 要复制)　　PP | L
EP | num_experts 且 EP | (TP × DP)　　Ulysses-CP | num_heads
动图 6:最小卡数与组合合法性
训练按 AdamW + ZeRO-3 的 16 B/param 计,并粗估一份重计算后的激活;推理按 bf16 权重 + 单条满序列 KV 计。 可用率取 0.88。结果是下界,真实部署还要留通信缓冲与调度余量。

十二、要点

01
量级差三个数量级

同口径下(每 micro-batch)EP 约 70 GiB、TP 约 17.5 GiB、CP 约 1–2 GiB、PP 每边界只有 64 MiB。选型前先知道自己在哪个量级,比任何调参都重要。

07
加 DP 卡不会降低每卡通信量

ZeRO-3 的 All-Gather 必须把参数拼回完整一份才能算,所以每卡收发量 ≈ 3Pb,与 DP 度无关。DP 摊薄的是 batch,不是通信。

02
Megatron-SP 免费,ZeRO-3 不免费

All-Reduce = RS + AG,所以 SP 把它拆开后通信量一字未变,省的激活显存是白拿的。但 ZeRO-3 是 3Pb 对朴素 DP 的 2Pb,多 50%,这是分片存储的真实代价。

03
只有 TP 与 S 强耦合且每层同步

TP 通信量正比于 L·B·S·H,80 层就是 320 次集合通信。这决定了它必须在 NVLink 域内,也决定了它是长序列下最先失控的那个。

04
EP 的放大系数是 min(k, N)

不是 k。多个选中专家落在同一张卡时只发一次。top-k 越大、EP 度越大,All-to-All 越重,而且怕路由长尾 —— 这是 EPLB 的由来。

05
Ulysses 与 Ring 的走势相反

Ulysses ~ O(1/N) 递减但被 head 数卡死;Ring ~ O(1) 不随 N 下降但没有上限。交叉点在 N≈4–8,这就是选型分水岭。

06
排布比选型更容易出事

TP 进 NVLink、PP 走最外层、DP 因为能和反向重叠可以往外放。同样的并行度组合,排布错了性能能差一个数量级,而这一步不会报错。

通信量按 ring 算法的每卡收发字节数估算,忽略延迟项、实现常数与重叠效果,只保留与 B/S/H/L/N 的比例关系, 用于横向比较量级,不等于实测。最小卡数为显存下界,未计通信缓冲与调度余量。
