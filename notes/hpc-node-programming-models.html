2026-09-01 HPCOpenMPSIMDCUDAOpenCLSYCL

节点级编程模型:OpenMP GPU、SIMD、同步、OpenCL、SYCL 与 CUDA Node-Level Programming Models: OpenMP GPU, SIMD, Sync, OpenCL, SYCL, CUDA

TUM / LRZ 的 BEAST 实验课(Evaluierung moderner HPC-Architekturen und -Beschleuniger)范围写得很清楚:节点内,不讲 MPI 集群。任务围着多核 CPU 和加速器转,大纲点名六件事 —— OpenMP(含 GPU offload)、SIMD、同步、OpenCL、SYCL、CUDA。BEAST(Bavarian Energy, Architecture and Software Testbed)是 LRZ 用来摸新型号、测能耗、给 SuperMUC-NG 后继机做 co-design 的试验床,不是对外服务;课上能碰到的硬件来自 Intel、AMD、NVIDIA、Marvell、Fujitsu 这一档,后来还加过 Cerebras 这类更偏门的加速器。

课程原文里 SuperMUC-NG「2020 年 6 月 Top500 第 13」是当时的定位,不是今天的排名。对我有用的是那句话的后半:先在节点上把一种架构吃透,再谈怎么把它编进下一台大机器。这篇是上课前的地图,不是实验报告。

一句话总览: 大纲里的六件事不是六座孤岛。SIMD 和同步是横切机制,在每一种模型里都会再出现一次;OpenMP / CUDA / OpenCL / SYCL 是同一套执行层次上的四个 API,差别主要在「谁写 kernel、数据怎么搬、能跑上哪家硬件」。先把名字对齐,再上机,才不会把 team、block、work-group 当成三件不同的东西。

0 · 课在哪一层

HPC 程序通常叠三层:进程间(MPI)→ 节点内线程/队(OpenMP、CUDA grid)→ 核内向量(SIMD / warp)。这门课停在后两层。一个节点上你真正要调度的,是「若干 CPU 核 + 零到多块加速器 + 它们之间那条又窄又贵的总线」。

1 · 先把名字对齐

异构设备几乎都按同一套三级来切工作:大范围切成组,组内再切成工作项,工作项在硬件上往往还被捆成一小波锁步执行。对照关系可以当字典用 —— 课上换 API 时,先在这张表里找同一行。

层次 OpenMP (device) CUDA OpenCL SYCL
整次发射 target 区域 kernel launch NDRange parallel_for / nd_range
粗粒度组 teams(league of teams) grid of blocks work-groups work-groups
组内并行 parallel 里的 threads threads in a block work-items work-items
锁步向量 simd / 实现定义 warp(NVIDIA 32) sub-group sub-group
组内共享内存 team 局部 / allocate __shared__ __local local_accessor
组内栅栏 barrier __syncthreads barrier(CLK_LOCAL_MEM_FENCE) group_barrier
记一个方向就够: CUDA 的 block = OpenCL/SYCL 的 work-group = OpenMP 的 team。能在这一层共享的内存,换个 API 只是换关键字;不能跨组同步(除非 cooperative launch 这类扩展),这条在四套模型里都成立。

2 · SIMD:核里面那条向量带

SIMD(Single Instruction, Multiple Data)是一条指令同时喂给多个数据通道。CPU 上它长在每个核的向量寄存器里:AVX2 是 256-bit,AVX-512 是 512-bit(16 个 float),ARM 的 NEON 通常 128-bit,Fujitsu A64FX / 部分 ARM 则是长度可伸缩的 SVE。编译器自动向量化、#pragma omp simd、手写 intrinsic,是同一件事的三个控制旋钮,从「听天由命」到「我指定通道数」。

上课时值得主动查的三件事:

  • 对齐与单位跨步。 aligned(A:64)、restrict / __restrict 告诉编译器没有别名。跨步不是 1 的访问会变成 gather/scatter,向量化收益很快被吃光。
  • 报告,不要猜。 Intel -qopt-report=3、Clang -Rpass=loop-vectorize、NVIDIA -Minfo=vect。报告里写 vectorized 才算数。
  • 和 GPU 的 SIMT 不要混名。 GPU warp 也是「一拍多数据」,但编程模型按线程写,硬件再把相邻线程捆成 warp。CPU SIMD 是你(或编译器)在指令级把循环切成向量;GPU SIMT 是硬件把标量线程锁步执行。发散(if 让 warp 里一半走 A、一半走 B)会把一拍拆成两拍串行。
#pragma omp simd aligned(A, B, C: 64)
for (int i = 0; i < N; ++i)
    C[i] = A[i] + B[i];   /* 编译器负责挑 AVX-512 / SVE 宽度 */

3 · 同步:每个边界一把锁

并行程序里「算得快」和「算得对」之间隔的就是同步。课把 synchronization 单列一项,是因为它不属于某一个 API,而是每个 API 都要你显式或隐式选一种。

  • Barrier / 栅栏。 OpenMP 并行区末尾默认有一道隐式 barrier(nowait 才拿掉);CUDA 的 __syncthreads() 只在 block 内有效;warp 内用 __syncwarp。跨 block 的栅栏不是默认能力。
  • 互斥 vs 原子 vs 规约。 critical 是一把大锁;atomic 是一条硬件原子;reduction 才是 HPC 里该先伸手去拿的 —— 它把「每人一份私有累加器,最后再合」这个模式写进运行时,避免伪共享。
  • 伪共享(false sharing)。 两个线程写同一 cache line(常见 64 B)里的不同字节,一致性协议仍当它们在抢。OpenMP 里给每个线程的累加器做 padding,或直接用 reduction,这个坑在 CPU 多核实验里几乎必现。
  • 内存序。 C++ / OpenMP 5.x / CUDA 原子都有 relaxed / acquire-release / seq_cst。计数器用 relaxed 通常够;发布指针给别的线程看,就要 acquire-release。默认 seq_cst 正确但贵,报告里值得写你选了哪一档。
  • 数据传输也是同步。 cudaMemcpy、OpenMP map、SYCL accessor 的依赖图,本质都是「这边写完,那边才能读」。把 H2D/D2H 算进或不算进计时,会让同一段 kernel 的「加速比」差出一个数量级。
OpenMP GPU 的静默回退: 如果 offload 失败(没链上 libomptarget、没 GPU、编译目标不对),实现可以改在 CPU 上跑,程序照样「正确」。测加速比之前先 OMP_TARGET_OFFLOAD=mandatory,失败就失败,不要拿一个其实跑在主机上的数字去写报告。

4 · OpenMP:同一套 pragma,从多核接到 GPU

OpenMP 的卖点是增量并行:串行循环上插 pragma,编译器负责 outline 出线程或 device kernel。CPU 上 parallel for 管核;向量化用 simd;从 4.0/4.5 起,target 把同一思路接到加速器。课标「OpenMP(用于 GPU)」,指的就是后面这条,不是把 CPU OpenMP 再讲一遍。

GPU 上那串组合 pragma 可以按层次拆:

  1. target —— 把区域丢到设备,并建立一份 data environment
    map(to: A[0:N]) 进、map(from: C[0:N]) 出。target data / enter data 用来避免每个循环都来回拷。
  2. teams —— 在设备上拉起一支 league,对应 CUDA grid
    每个 team 有自己的 master。没有 teams,很多 GPU 运行时只能动到一小块计算单元。
  3. distribute —— 把外层迭代分给各个 team
    只分到 team 一级,还没动 team 内部的线程。
  4. parallel for —— team 内部再切,对应 block 内的 threads
    常用合体:#pragma omp target teams distribute parallel for。二维循环再加 collapse(2)。
#pragma omp target teams distribute parallel for \
    map(to: A[0:N], B[0:N]) map(from: C[0:N])
for (int i = 0; i < N; ++i)
    C[i] = A[i] + B[i];

厂商编译器不是同一条命令:

编译器典型旗标常见目标
GCC-fopenmp -foffload=nvptx-none 或 amdgcn-amdhsaNVIDIA / AMD GPU
Clang/LLVM-fopenmp -fopenmp-targets=nvptx64-nvidia-cudaNVIDIA;AMD 用 amdgcn-amd-amdhsa
NVIDIA nvc-mp=gpu -Minfo=mp,optNVIDIA;-gpu=managed 走统一内存
Intel icx-fiopenmp -fopenmp-targets=spir64Intel GPU(Level Zero / SPIR-V)

数据生命周期是 OpenMP GPU 实验里比 kernel 本身更容易丢分的部分。循环外用 target data 把数组钉在设备上,再在里面多次 target 只 map(tofrom:) 真正变的那一块。LRZ 自己的 OpenMP GPU lab 也是按「先能 offload,再管 data management」这个顺序排的。

5 · CUDA:在 NVIDIA 上把控制权拿满

CUDA 是这张表里控制粒度最细、可移植性最窄的一档。kernel 用 __global__ 写,发射用 <<<grid, block>>>,线程坐标是 blockIdx * blockDim + threadIdx。内存分成 global / shared / local / constant,shared memory 就是 block 级暂存,对应上面那张表的「组内共享」。

  • 合并访存(coalescing)。 同一 warp 的线程读连续地址,硬件合成一次事务;按列读二维数组会把带宽打成碎片。这是 CUDA 实验里最稳的「架构相关」观察。
  • Occupancy ≠ 最快。 寄存器和 shared memory 用多用少,决定一个 SM 能常驻多少 warp。Occupancy 高有助于藏延迟,但不是目标函数;Nsight Compute 里看实际吞吐和 stall 理由。
  • Stream。 默认流是同步的。独立 stream 才能把 H2D、kernel、D2H 叠起来 —— 又回到「同步」那一节:你要显式决定哪些可以重叠。
  • 统一内存。 cudaMallocManaged 让代码变短,page migration 的代价会写进第一次 touch。和 OpenMP -gpu=managed、SYCL USM shared 是同一类权衡。

AMD 上的对位不是 CUDA,是 HIP(接口几乎一对一,后端换 ROCm)。课如果给 AMD GPU,不要硬套 nvcc;SYCL 或 OpenMP offload 往往比手写一份 CUDA、再指望 HIPIFY 更符合「评架构」的目标。

6 · OpenCL:最「标准」,也最啰嗦

OpenCL 把异构计算拆成一条显式流水线:platform → device → context → queue → program → kernel → NDRange。kernel 用 OpenCL C 写成字符串或预编译的 SPIR-V,host 侧全是 C API。它能跑的地方最杂(GPU、CPU、历史上还有 FPGA),代价是启动一个 SAXPY 就要写几十行样板。 

__kernel void add(__global const float* A,
                  __global const float* B,
                  __global float* C) {
    int i = get_global_id(0);
    C[i] = A[i] + B[i];
}

为什么课还要教它:因为 CUDA / SYCL / OpenMP offload 的设备侧执行模型,几乎都是从这套 NDRange 语义长出来的。get_global_id / get_local_id / get_group_id 对上 CUDA 的 threadIdx 三件套之后,后面换 API 只是换皮。新代码更常经 SYCL 或 OpenMP 到达设备;OpenCL 仍是「看见运行时到底在干什么」的底图,也是某些非 NVIDIA 设备上仍能找到的最低公共 API。

7 · SYCL:单源 C++,后端再接各家

SYCL 的承诺是:一份现代 C++ ,kernel 就写在 lambda 里,由实现接到 CUDA、HIP、Level Zero 或 OpenCL。Intel DPC++(icpx -fsycl)和 AdaptiveCpp(原 hipSYCL)是课上最可能碰到的两套。SYCL 2020 起有两条数据路:

Buffer + accessor

运行时根据 accessor 的读写意图建 DAG,自己插入拷贝。安全、啰嗦少一些,调试时要习惯「这次 accessor 到底触发了一次 H2D 没有」。

USM

malloc_device / malloc_shared / malloc_host。指针语义接近 CUDA。device 指针不能在 host 解引用;shared 可以,但迁移成本和 managed CUDA 同类。

q.parallel_for(N, [=](sycl::id<1> i) {
    C[i] = A[i] + B[i];
}).wait();

SYCL 不是「CUDA 的开源版」。它在 Intel GPU 上是一等公民,在 NVIDIA / AMD 上取决于你的编译器有没有把对应 backend 编进来。课上换节点时,第一件事是 sycl-ls(或实现提供的 device 列表)确认 queue 绑的是你以为的那块设备,而不是偷偷落到 OpenCL CPU 回退。

8 · 同一份 SAXPY,四个 API

下面这块可以来回切。四段代码做同一件事:C[i] = A[i] + B[i]。差别不在算术,在谁负责切工作、谁负责搬数据、谁负责等结束。

9 · BEAST 上谁能跑什么

LRZ 公开写过 BEAST 上出现过 AMD、Cerebras、Fujitsu、Intel、NVIDIA 等处理器,课程简介还点了 Marvell。具体机架清单会变,所以下面这张表按架构家族 × 编程模型来记,不绑定某一代 SKU。Cerebras 走自己的 SDK,不在这六件事里,别用 CUDA 思维硬套。

硬件家族 OpenMP SIMD CUDA OpenCL SYCL
Intel CPU / GPU CPU + offload AVX-512 / 隐式 — 有 一等(oneAPI)
AMD CPU / Instinct CPU + offload AVX2/512 · wave64/32 经 HIP 有 AdaptiveCpp / DPC++
NVIDIA GPU nvc/clang offload warp 32 原生 有 CUDA backend
Marvell ARM CPU OpenMP NEON / SVE — 视栈 视栈
Fujitsu A64FX 强项 SVE 512-bit — 有限 有限

一等/直接支持 间接或看软件栈 基本不走这条路

同一算法、换节点,才是这门课的单位。 厂商短讲听的是「这块硅片的向量宽、缓存、HBM、互联」。报告里要对齐的是:问题规模、是否含拷贝、编译器旗标、绑核(OMP_PROC_BIND / OMP_PLACES)、以及设备到底是不是你以为的那一块。GFLOP/s 单独出现没有对照价值。

10 · 上课前我给自己的清单

  • 能把 team / block / work-group 画在同一层,不靠背定义。
  • CPU 上先看向量化报告,再谈 OpenMP 线程数;线程数 × SIMD 宽度才是峰值口径。
  • GPU 上先证明 kernel 跑在设备上,再谈快慢。mandatory offload、SYCL device 列表、CUDA nvidia-smi 是三种等价的「别骗自己」。
  • 计时拆三截:H2D、kernel、D2H。加速比要写清楚包不包含搬运。
  • 同步实验优先做 reduction / false sharing / barrier 的代价,而不是再写一把大 critical。
  • 可移植性实验:同一份 OpenMP 或 SYCL,在 NVIDIA 和 Intel/AMD 节点上编过去 —— 这比在一块卡上把 CUDA occupancy 调到理论峰值,更贴近 BEAST 存在的理由。
预期技能课表只写了「C 要熟,对体系结构和低层优化有兴趣」。六个名词里,真正要带上机的心态是:先画层次,再选 API,最后才碰旗标。
